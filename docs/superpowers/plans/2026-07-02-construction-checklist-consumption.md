# Construction Checklist Consumption Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the construction collection page consume the same configured field checklist that users define in project field configuration.

**Architecture:** Keep the existing backend construction contract unchanged because it already returns `construction_fields` and `photo_slots` from the project field schema. Add a frontend checklist layer in `ConstructionView.vue` that turns configured fields, photo slots, and platform KPI requirements into visible completion items for the active work order, then reuse the existing required-field and missing-photo checks for submit blocking.

**Tech Stack:** Vue 3, TypeScript, Element Plus, existing platform construction APIs, focused Node guard script, local browser smoke validation.

---

## Context

- Production baseline: `production/V3/3.0.71`.
- Feature branch: `pm-platform/project-drafts`.
- Lead role: Backend Construction And Review Agent with Frontend Field Graph Agent contract awareness.
- User need: the field graph should not stop at configuration; construction workers should see the same configured fields as a concrete collection checklist.
- Data safety: no database migration, no backend API change, no production data edit, no version bump, no tag, no deployment.
