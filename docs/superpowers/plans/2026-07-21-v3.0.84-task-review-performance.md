# V3.0.84 Task Claim and Review Performance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the task claim page and review workbench load from a shared server snapshot and a true 20-row review queue instead of recomputing and transferring full project data on every visit.

**Architecture:** Add a task-specific stale-while-revalidate cache that persists per-team snapshots and refreshes them in one background worker. Add a dedicated review queue repository method that filters, counts, orders, and paginates before payload construction, then migrate both Vue pages to the new bounded APIs with request-epoch protection.

**Tech Stack:** Python 3.11+, FastAPI, SQLAlchemy 2, PostgreSQL/JSON state backends, Vue 3, TypeScript, Element Plus, Node test runner, pytest.

## Global Constraints

- Production base is commit `2b66903cbca50b43d5312a3e875d7d47244cd1f1` on `production/V3/3.0.83`.
- Target branch and version are `production/V3/3.0.84` and `V3.0.84`.
- Task snapshots refresh every `60` seconds and return stale data while one background refresh runs.
- Review group pages contain at most `20` rows.
- Search and status counts cover the complete task result, not only the current page.
- Existing `/tasks`, `/tasks/status`, and `/tasks/{task_id}/groups` contracts remain compatible.
- No browser-side barcode or OCR processing is introduced.
- No V3.1.0 export, archive, or barcode-rule changes are included.
- Every production code change starts with a failing focused test.

```python
TaskSnapshotBuilder = Callable[[str], dict[str, Any]]


class TaskSnapshotCache:
    def __init__(self, *, cache_root: Path | None = None, interval_seconds: int | None = None, enabled: bool | None = None) -> None:
        configured = interval_seconds if interval_seconds is not None else settings.task_snapshot_cache_seconds
        self.interval_seconds = max(30, int(configured))
        self.enabled = settings.task_snapshot_cache_enabled if enabled is None else bool(enabled)
        self.cache_root = cache_root or default_task_snapshot_cache_root()
        self._lock = threading.RLock()
        self._memory: dict[str, dict[str, Any]] = {}
        self._refreshing: set[str] = set()
        self._stop_event = threading.Event()
        self._worker: threading.Thread | None = None
        self._known_teams: set[str] = set()

    def get(self, team_id: str, builder: TaskSnapshotBuilder, *, force_refresh: bool = False) -> dict[str, Any]:
        safe_team_id = _safe_team_id(team_id)
        self._known_teams.add(safe_team_id)
        if not self.enabled or force_refresh:
            return self.refresh(safe_team_id, builder, source="refresh")
        snapshot = self._snapshot_for_team(safe_team_id)
        if snapshot is None:
            return self.refresh(safe_team_id, builder, source="cold")
        stale = self._is_stale(snapshot)
        if stale:
            self.refresh_async(safe_team_id, builder)
        return self._payload_with_cache_meta(snapshot, stale=stale)
```

Implement file persistence with atomic temporary-file replacement, team validation using top-level `payload["team_id"]`, one background thread per stale team, and one scheduler thread that loops over `_known_teams` every 60 seconds. A builder exception must leave the previous snapshot intact.

```javascript
export function createReviewQueueRequestEpoch() {
  let value = 0
  return {
    begin() { value += 1; return value },
    invalidate() { value += 1 },
    isCurrent(candidate) { return candidate === value },
  }
}

export function nextReviewQueuePageAfterMutation({ page, pageSize, total, remainingOnPage }) {
  if (remainingOnPage > 0 || page <= 1) return Math.max(1, page)
  return Math.max(1, Math.min(page - 1, Math.ceil(Math.max(0, total - 1) / pageSize)))
}
```
