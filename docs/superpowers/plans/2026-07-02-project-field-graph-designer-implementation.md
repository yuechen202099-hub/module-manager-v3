# Project Field Graph Designer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make project field configuration understandable as a visual hierarchy that operators can adjust by dragging child fields under the aggregate field or primary field.

**Architecture:** Keep `ProjectsView.vue` as the owner of the reactive `schemaForm` and keep all saves on the existing `buildWorkItemSchemaPayload(schemaForm)` path. Improve `FieldGraphDesigner.vue` as a UI-only layer over the same field schema data: it reads aggregate, primary, custom, platform-required, and template-preview fields, then emits `update-parent` and `update-field` without changing backend contracts.

**Tech Stack:** Vue 3, TypeScript, Element Plus, existing project field schema types, focused Node guard scripts, local browser smoke validation.

```ts
function isSelected(type: FieldSelectionType, index = -1) {
  return selectedField.value?.type === type && selectedField.value.index === index
}
```

- [x] **Step 2: Add readable parent labels**

Add:

```ts
function selectedParentLabel(field: FieldForm) {
  const parentKey = field.parentKey || primaryKey.value
  if (parentKey === aggregateKey.value) return fieldTitle(props.aggregateField, '聚合字段')
  if (parentKey === primaryKey.value) return fieldTitle(props.primaryField, '主字段')
  return parentKey || '项目对象'
}
```
