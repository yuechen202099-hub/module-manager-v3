# V3.2.1 KPI Package Integrity Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the reviewed V3.2.1 KPI source integrity lock deterministic on Windows and enforce the same SHA-256 lock against the actual KPI source bytes inside every release ZIP.

**Architecture:** Pin the two reviewed KPI source paths to LF in `.gitattributes`, keep `scripts/verify_v3_2_1_release.py` as the single owner of their reviewed SHA-256 values, and have `scripts/verify-client-release.py` load those values and hash the corresponding ZIP members. Release-test fixtures must package the real reviewed source bytes by default so a valid fixture proves the production path, while targeted mutations prove that altered or CRLF-converted members are rejected.

**Tech Stack:** Git attributes, Python 3.12, `hashlib`, `zipfile`, pytest, PowerShell release gates.

## Global Constraints

- Production baseline remains `V3.2.0`; candidate remains `V3.2.1`; branch remains `production/V3/3.2.1`.
- Do not change `v2-web/src/components/InstallerKpiDialog.vue` or `v2-web/src/utils/installerKpi.ts`; this task attests the already-reviewed bytes.
- `v2-web/src/components/InstallerKpiDialog.vue` and `v2-web/src/utils/installerKpi.ts` must both use Git attributes `text eol=lf`.
- `scripts/verify_v3_2_1_release.py::KPI_SOURCE_SHA256` remains the single reviewed-digest source used by source and package verification.
- A release ZIP must fail when either locked KPI member is missing, byte-modified, or CRLF-converted.
- The release ZIP verifier must hash the member bytes returned by `ZipFile.read()`; it must not validate only member names or reproduce digest constants in a second table.
- Keep `SOURCE_COMMIT` validation, tracked-member validation, Vue asset manifest validation, pending candidate truth checks, and all historical V3.2.0 verifiers unchanged.
- Do not stage or package `.env`, `.pem`, data, uploads, caches, database dumps, secrets, `node_modules`, `build`, release archives, or the reserved untracked Vue assets.
- No production access, backup, deployment, branch push, or tag creation occurs in this plan.
- Every behavior change follows RED, verify RED, GREEN, verify GREEN.

    path = Path(__file__).with_name("verify_v3_2_1_release.py")

- [ ] **Step 5: Verify actual ZIP member bytes**

Add this helper in `scripts/verify-client-release.py`:

```python
def verify_packaged_kpi_source_integrity(
    archive: zipfile.ZipFile,
    names: set[str],
) -> None:
    v321_verifier = load_v321_release_verifier()
    expected_digests = dict(v321_verifier.KPI_SOURCE_SHA256)
    for relative_path, expected_digest in expected_digests.items():
        if relative_path not in names:
            fail(f"Missing reviewed KPI source member: {relative_path}")
        actual_digest = hashlib.sha256(archive.read(relative_path)).hexdigest()
        if actual_digest != expected_digest:
            fail(
                f"{relative_path}: packaged KPI source integrity mismatch: "
                f"expected SHA-256 {expected_digest}, got {actual_digest}"
            )
```

Call it in `verify_package()` immediately after the existing required-file check and before lifecycle/version truth checks:

```python
missing = sorted(REQUIRED_FILES - names)
if missing:
    fail("Missing required release files: " + ", ".join(missing))
verify_packaged_kpi_source_integrity(archive, names)
```

The verifier must use `archive.read(relative_path)` without decoding or newline normalization.
