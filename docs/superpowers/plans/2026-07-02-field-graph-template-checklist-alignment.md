# Field Graph Template Checklist Alignment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect the field graph directly to template download, template validation, mid-project takeover, and construction required-checklist guidance.

**Architecture:** Keep the backend template service and existing project template APIs unchanged. Add UI-only actions to `FieldGraphDesigner.vue` that emit `template-action` events, then let `ProjectsView.vue` translate those events into the existing `downloadTemplate()` and `requestTemplateValidation()` flows for the current `schemaProject`.

**Tech Stack:** Vue 3, TypeScript, Element Plus, existing `ProjectTemplateType`, focused Node guard scripts, local browser smoke validation.

---

## Context

- Production baseline: `production/V3/3.0.71`.
- Feature branch: `pm-platform/project-drafts`.
- Lead role: Frontend Field Graph Agent with Import And Template Agent contract awareness.
- User need: the user should not have to leave field configuration to understand which template to download, which template to validate, and which fields become site-required collection.
- Data safety: no database migration, no backend contract change, no production data edit, no version bump, no tag, no deployment.

### Task 3: Handle actions in `ProjectsView.vue`

- [x] **Step 1: Add `handleSchemaTemplateAction`**

Expected behavior:

```ts
function handleSchemaTemplateAction(payload) {
  const project = schemaProject.value
  if (!project) return
  if (payload.action === 'validate') {
    requestTemplateValidation(project, payload.templateType)
    return
  }
  void downloadTemplate(project, payload.templateType)
}
```

- [x] **Step 2: Bind the event**

Expected template:

```vue
@template-action="handleSchemaTemplateAction"
```
