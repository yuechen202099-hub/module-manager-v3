# V3.2.0 Data Review And Export Center Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the reviewer-role and terminal-review workflow with an admin-only, group-level data review center, dashboard drill-down links, and one server-backed export center in production version `V3.2.0`.

**Architecture:** Keep the existing group mutation, barcode verification, automatic archive, delivery-package cache, and KPI calculations as the source of truth. Add one lightweight server-paginated data-center query contract and one export-center facade over existing export builders, then migrate frontend entry points and permissions without deleting historical review fields or audit records.

**Tech Stack:** FastAPI, Pydantic, SQLAlchemy 2, PostgreSQL/Alembic, JSON compatibility repository, pytest, Vue 3, TypeScript, Element Plus, Vue Router, Vite.

## Global Constraints

- Production baseline is commit `6e8e8e33fdb8d9228d7b93f3797515c777ec1584`; release version is exactly `V3.2.0`.
- Valid login roles are exactly `admin` and `constructor`; reviewer-only accounts are disabled while historical reviewer fields and audit rows remain unchanged.
- Data center and export center are administrator-only; constructors cannot recover access through old URLs, old tokens, or direct API requests.
- `/task-hall` redirects to `/global-search`; `/review/:groupId` redirects to `/global-search?group_id=:groupId&review=1`.
- Data-center rows are material groups or unmatched evidence, never terminal-grouped review tasks.
- Every related detail list uses server pagination, defaults to 20 rows, accepts only `20`, `50`, or `100`, and synchronizes page, page size, sort, and filters to the URL.
- Frontend filter changes invalidate older requests so a stale response cannot overwrite the latest result.
- Photos and full recognition evidence are loaded only after a review dialog opens; closing the dialog aborts requests and releases object URLs.
- Classification-complete plus group-level barcode pass plus valid formal identity automatically archives and queues delivery cache generation.
- Unmatched evidence can attach only to a uniquely identified existing group or terminal; it must never create `00000000` or another placeholder work order.
- Every mutation records administrator, timestamp, reason, before/after values, and source page; rollback to unconstructed clears photos, module number, collector number, and barcode-pass evidence.
- Dashboard visualizations drill down to URL-filtered data-center results and do not keep duplicate detail dialogs or business export controls.
- Export center is the only frontend entry for business exports; import-template downloads stay beside their import dialogs.
- Device exports are four independent one-column Excel files: terminal, meter, module, collector; values are trimmed, non-empty, non-placeholder, unique, stably sorted, preserved as Excel text, and protected from formula injection.
- Final-delivery downloads reuse the existing background cache/queue and perform one server-side terminal readiness query instead of probing export endpoints in a frontend loop.
- Original KPI formulas, fields, and export semantics remain unchanged.
- Release requires full backend tests, frontend type-check/build, migration tests, focused page/API checks, independent review with `Critical=0` and `Important=0`, production backup, package hash verification, cutover, and live health checks.

```python
SUPPORTED_PAGE_SIZES = {20, 50, 100}

class DataCenterQuery(BaseModel):
    data_type: Literal["all", "group", "unmatched"] = "all"
    construction_status: Literal["all", "unconstructed", "in_progress", "completed"] = "all"
    archive_status: Literal["all", "unarchived", "pending", "archived"] = "all"
    barcode_status: Literal["all", "passed", "manual", "mismatched", "unreadable", "ineligible"] = "all"
    classification_status: Literal["all", "complete", "incomplete"] = "all"
    exception_status: str = ""
    installer: str = ""
    date_from: date | None = None
    date_to: date | None = None
    terminal: str = ""
    query: str = ""
    page: int = Field(default=1, ge=1)
    page_size: int = Field(default=20)
    sort: Literal["updated_desc", "updated_asc", "terminal_asc"] = "updated_desc"

    @field_validator("page_size")
    def supported_page_size(cls, value: int) -> int:
        if value not in SUPPORTED_PAGE_SIZES:
            raise ValueError("page_size must be one of 20, 50, 100")
        return value
```
