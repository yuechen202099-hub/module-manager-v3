# 任务派发页终端资料导出设计

## 1. 决策与目标

本设计在 `V3.2.26` 生产基线上恢复一种受控、低资源的资料导出能力，但不恢复已下线的旧“导出中心”。新入口只放在现有任务派发页面，由管理员按终端设置应还采集器数量、选择终端并导出。服务器不生成 ZIP、不在磁盘落地整包、不缓存交付包；浏览器将文件直接写入管理员选择的本地文件夹。

目标如下：

- 每个终端生成独立目录，每块已施工电表按模块号生成子目录并保留两张业务照片。
- 终端目录下单独生成采集器照片目录、终端资料表和必要时的补充采集器表。
- 优先使用施工数据中的同号实物采集器，不足时从采集器池随机补齐，一对一占用且禁止跨终端重复使用。
- 导出前严格拦截已施工数据中的模块异常、模块号重复和一表多模块。
- 未施工数据不参与校验，也不导出；部分施工终端只导出已施工且通过校验的数据。
- 利用 OSS 到同平台服务器的内网免费流量，以约 `2 Mbps` 单路限速流式中转，适配服务器固定 `3 Mbps` 公网带宽。
- 支持预检、进度、暂停、继续、失败重试、断点续传、重复导出复用分配和完整审计。

本设计是新的终端资料导出子系统。旧 `/exports` 页面、旧导出中心路由、服务器端 ZIP/Excel 整包生成和交付包 worker 继续保持退休状态。

## 2. 使用范围与权限

### 2.1 页面范围

不新增导出页面或前端路由，只修改现有任务派发页面：

- 每个终端卡片增加勾选框。
- 每个终端卡片增加“应还采集器数量”输入框。
- 每个终端卡片增加“导出资料”按钮。
- 页面顶部增加“全选当前结果”和“一键导出已勾选终端”。
- 页面顶部显示当前导出任务、进度、预计剩余时间、暂停、继续和失败重试入口。
- 仅管理员可见并可调用相关接口；施工员页面、路由和权限保持不变。

“全选当前结果”只选择当前筛选结果中具备已施工数据的终端，不越过筛选条件选择隐藏数据。存在预检问题的终端可以先被勾选，但正式预检后会被阻止并显示中文原因；已完成过导出的终端仍可再次选择，并复用原有采集器分配。

### 2.2 卡片排序

任务派发页终端卡片按以下固定顺序排列：

1. 已标记“优先施工”的终端在前。
2. 同一优先级内按现有平台完成率从高到低。
3. 完成率相同时按终端号升序。

排序只影响展示，不改变导出资格、采集器分配或任务执行顺序。批量导出按页面选择结果经上述排序后的终端顺序逐个执行。

## 3. 导出业务范围

### 3.1 已施工口径

导出和校验以平台现有“已施工”业务状态为准：

- 未施工表计不参与模块重复、一表多模块、字段完整性、照片完整性或采集器数量计算。
- 未施工表计不写入目录、照片或 Excel。
- 一个终端没有任何已施工表计时，不能导出，并显示“该终端暂无已施工资料”。
- 一个终端只有部分表计已施工时，只处理已施工表计；未施工部分不阻止该终端导出。
- 施工状态在预检后发生变化时，该终端暂停并要求重新预检。

### 3.2 有效数据口径

只使用当前项目内有效、未软删除的施工业务记录和有效照片。照片条数不是表计或模块的计数依据；同一资料组的“模块与电能表”和“改造后”两张照片共享同一业务模块号，不构成模块重复。

逻辑校验单位是已施工表计业务资料组。若相同模块号出现在两个不同有效资料组中，即使两个资料组的表号相同，也属于模块号重复。

## 4. 导出前置校验

### 4.1 项目级模块完整性

每次预检都在当前项目全部有效、已施工资料组范围内重新计算，不能只检查当前终端。必须同时满足：

- 每个已施工资料组的表号非空。
- 每个已施工资料组的模块号非空。
- 每个模块号只能出现在一个有效、已施工资料组中。
- 同一表号只能对应一个不同的模块号，禁止“一表多模块”。
- 已施工资料组不存在任何未关闭的模块类异常，尤其是模块缺失、模块号重复、模块冲突和一表多模块。

模块号和表号比较使用平台现行业务标准化规则；展示和导出仍保留原始号码。标准化后相同即视为相同号码，不能通过空格、大小写或格式差异绕过重复校验。

如果冲突跨越两个或多个终端，所有受冲突影响的终端均被阻止；其他无冲突终端可继续导出。错误信息必须使用中文，并至少列出异常类型、表号、模块号和相关终端号，例如：

- `模块号 123456 在终端 A、终端 B 的两个已施工资料组中重复。`
- `表号 3500001 同时对应模块号 M001、M002，属于一表多模块。`

已人工确认修复并关闭的异常不再阻止导出；仅页面展示为“正式通过”但仍存在未关闭模块异常时，仍然阻止导出。

### 4.2 表计字段与照片完整性

每个准备导出的已施工资料组必须具备：

- 表号。
- 模块号。
- 安装地址；地址以总清单为唯一来源，不从照片或其他临时字段覆盖。
- 一张有效的“模块与电能表”照片。
- 一张有效的“改造后”照片。

表号、模块号、地址或两张必需照片缺失时，只阻止对应终端并显示中文原因，其他正常终端继续。不存在“其他照片”导出槽位。

### 4.3 采集器不作为照片异常

采集器照片缺失不属于资料异常，也不阻止导出。采集器号为空但终端没有采集器需求时不阻止；终端存在应还采集器需求时，由同号实物匹配和采集器池分配解决。分配成功但找不到照片时仍保留采集器号，只是不生成对应图片，并在审计中记录“无可用照片”。

### 4.4 预检结果与批量执行

预检以终端为单位返回 `可导出`、`被阻止` 或 `需重新预检`：

- 普通字段、照片或模块异常只阻止相关终端，批量中的其他正常终端可以继续。
- 采集器池库存不足属于批量分配约束：本批次不开始正式分配和下载，统一显示总缺口及各终端缺口，避免先消耗部分库存后再失败。
- 预检结果包含基于施工数据、异常状态、有效照片和采集器库存计算的版本指纹。正式锁定前版本变化则拒绝旧预检结果。

## 5. 应还采集器数量

管理员可在任务派发时提前为每个终端设置非负整数“应还采集器数量”。系统计算最终需求数量：

```text
最终应还采集器数量 = max（已施工数据中采集器号去重数量，管理员填写数量）
```

规则示例：

- 已施工数据有 `3` 个不同采集器号、管理员填写 `2`，最终数量为 `3`。
- 已施工数据有 `2` 个不同采集器号、管理员填写 `4`，最终数量为 `4`。
- 管理员未填写时按 `0` 处理，但仍不能低于已施工数据中的去重数量。

该参数按项目和终端持久化，记录最后修改人和时间。修改数量不会立即占用采集器池；只有正式导出锁定时才分配。数量小于已有去重数时前端提示“不能减少已有施工采集器需求”，后端仍以最大值为准。

## 6. 采集器匹配与占用

### 6.1 分配顺序

系统按以下顺序满足一个终端的最终需求数量：

1. 对已施工数据中的每个不同采集器号，优先查找盘点库中同号、有效、未被其他终端占用的实物采集器。
2. 同号实物不足或施工数据中的采集器号未找到实物时，从采集器池中随机选择有效、未占用的采集器替代。
3. 管理员填写数量高于施工数据去重数量时，多出的数量从采集器池随机补充，作为没有对应表计的额外采集器。

一个原施工采集器号服务多块电表时只形成一个采集器需求；分配到替代采集器后，终端资料表中这些电表行统一写入同一个最终采集器号。

### 6.2 一对一与重复导出

- 一个实物采集器在任意时刻只能被一个终端的有效分配占用。
- 正式导出锁定时，在数据库事务内锁定候选库存、创建分配和预留记录，禁止并发重复消费。
- 批量预检库存充足后仍需在正式锁定事务内再次核对；并发冲突时整批不开始并提示重新预检。
- 同一终端重复导出复用原有效分配，不再次消耗采集器池，也不随机更换已有结果。
- 导出失败、暂停或浏览器断开时保留预留，防止采集器被另一终端取得。
- 管理员可对未完成导出的终端执行“取消并释放”；已完成终端不能释放。
- 释放时只释放本次终端分配，不修改施工原始数据、盘点原始记录或 OSS 对象，并写入审计。

### 6.3 池不足

批量预检按选中终端的稳定顺序模拟复用和新增分配，但不写入占用。如果可用池数量不足，本批所有新分配均不落库、不开始下载，并返回：

- 本批所需总数。
- 可复用分配数。
- 可用同号实物数。
- 可用池数量。
- 总缺口。
- 每个终端的需求、已满足数和缺口。

## 7. 采集器照片选择

每个最终采集器只输出一张照片，按以下优先级选择：

1. 盘点库已有该实物采集器同号照片时，直接使用。
2. 同号实物已确认但盘点库无照片时，从当前终端对应原采集器号的已施工表计组中任选一张有效采集器照片。
3. 从池中补充或替换的采集器使用池内该实物自己的照片。
4. 仍无照片时不生成图片、不算异常、不阻止导出，并在终端资料和审计结果中保留采集器号及无照片状态。

“任选一张”必须是稳定选择：按有效照片的创建时间、照片主键升序取第一张，确保重复导出得到相同结果。照片只读，不重新压缩、不转码、不覆盖或移动 OSS 原对象。

## 8. 本地目录和文件命名

管理员在最新版 Windows Chrome 或 Edge 中选择一个本地根目录。每个终端生成：

```text
终端号/
├─ 模块号/
│  ├─ 模块与电能表.<原扩展名>
│  └─ 改造后.<原扩展名>
├─ 采集器/
│  ├─ 采集器号1.<原扩展名>
│  └─ 采集器号2.<原扩展名>
├─ 终端资料.xlsx
└─ 补充采集器.xlsx
```

规则如下：

- 终端号、模块号、表号和采集器号中的 Windows 非法文件名字符替换为全角安全字符，并保留 Excel 中的原始值。
- 模块号在项目级重复时已被预检阻止，正常情况下同一终端不会发生同名目录冲突。
- 为防止历史脏数据或并发变化造成覆盖，浏览器仍执行防御性检查：同一终端第二次出现相同模块目录名时使用 `模块号__表号`，并将该终端标为需重新预检，而不是静默覆盖文件。
- 照片沿用原有效扩展名；扩展名不可识别时根据已验证的内容类型选择安全扩展名。
- 不生成 ZIP，不重新压缩或转码照片。
- 不生成单独的“采集器清单”文件。
- 只有存在没有对应表计的额外采集器时才生成 `补充采集器.xlsx`。

### 8.1 终端资料.xlsx

每块已施工且通过校验的表计一行，至少包含：

- 表号。
- 地址。
- 模块号。
- 最终采集器号。

如果原采集器被池中实物替代，则写最终实物采集器号；同一采集器对应多块表时允许多行出现相同最终采集器号。采集器无照片不改变该字段。

### 8.2 补充采集器.xlsx

只列管理员填写数量高于施工采集器去重数量后产生、且没有对应表计的额外采集器，字段为：

- 采集器号。
- 照片文件名；无照片时留空。

没有额外采集器时不生成该文件。

## 9. OSS、服务器与浏览器数据流

### 9.1 数据流

采用“服务器内网读取 OSS、限速流式中转、浏览器逐文件落盘”：

1. 浏览器提交选中终端及最新预检指纹。
2. 后端完成项目级模块校验、终端资料校验、库存模拟和正式分配锁定。
3. 后端返回只包含必要元数据的导出清单，不返回 OSS 永久凭据。
4. 浏览器按终端顺序逐文件请求。
5. 后端通过 OSS 内网端点读取单个对象，并以约 `2 Mbps` 上限流式转发，不将完整对象加载进内存或写入服务器磁盘。
6. 浏览器使用 File System Access API 写入管理员选择的目录，并在每个文件完成后记录校验结果。
7. Excel 在浏览器端根据清单生成，服务器不生成或缓存 Excel、ZIP、目录树或临时交付包。

### 9.2 资源限制

- 全系统同一时间只允许一个正式导出任务进入下载态。
- 单任务只允许一个文件流，照片串行下载，不并发拉取 OSS。
- 服务端默认限速约 `2 Mbps`，为固定 `3 Mbps` 公网带宽预留约 `1 Mbps` 给施工、审阅和管理页面。
- OSS 到服务器使用同平台内网端点，不产生公网流量费用；若内网端点不可用，任务暂停并报错，不自动回退到可能计费的公网 OSS 地址。
- 服务器不落盘、不生成 ZIP、不保存完整照片字节；仅保存任务、清单摘要、分配、进度和审计元数据。

### 9.3 暂停、继续与断点续传

- 暂停停止发起下一个文件请求；正在传输的单个文件安全结束后进入暂停态。
- 浏览器断开时，后端释放全局下载执行槽，但保留任务、清单和采集器预留。
- 浏览器在 IndexedDB 保存任务 ID、本地目录授权引用、已完成文件的相对路径、大小和 SHA256。
- 页面刷新或浏览器重启后，管理员重新授权同一本地目录；客户端校验已完成文件，匹配者跳过，不匹配或缺失者重新下载。
- 后端以文件为最小恢复单位，不依赖 HTTP Range 续传单张照片；单张中断时只重下该文件，已校验文件不重复下载。
- 同一导出任务的清单版本不可变。源数据变化不会改写正在执行的清单，而是将尚未完成的相关终端标记为“需重新预检”并停止该终端。

## 10. 状态模型与并发

### 10.1 终端导出状态

终端导出状态至少包括：

- `not_prechecked`：未预检。
- `blocked`：存在字段、照片、模块或权限问题。
- `ready`：预检通过但尚未锁定。
- `reserved`：采集器已分配并预留。
- `downloading`：正在下载。
- `paused`：人工暂停或浏览器断开。
- `needs_recheck`：源数据或异常状态变化。
- `failed`：发生可重试失败。
- `completed`：本地全部必需文件已校验完成。
- `cancelled_released`：管理员取消并释放预留。

### 10.2 全局导出任务

后端用数据库租约实现全系统单任务执行，不能只依赖单进程内存锁。租约包含任务 ID、操作者、获取时间、心跳和过期时间；服务重启后过期租约可安全回收，但采集器预留不会自动释放。

任务可包含多个终端。终端之间串行执行；单个终端被普通资料异常阻止时跳过并继续其他正常终端，池不足或正式分配并发冲突时整批不开始。

### 10.3 数据持久化

实现阶段采用独立、可审计的数据边界，至少持久化：

- 项目终端的管理员应还采集器数量及修改审计。
- 导出任务、终端子任务、清单版本和状态。
- 原施工采集器号到最终实物采集器号的分配关系。
- 没有对应表计的额外采集器分配。
- 采集器预留、释放和完成状态。
- 每个文件的相对路径、来源照片、大小、SHA256、下载状态和重试次数。

数据库迁移只新增本功能所需表和索引，不重写既有施工、照片、盘点或异常历史数据。准确表名、字段和索引在实施计划中依据当前模型确定，但必须保持上述职责边界。

## 11. 审计与留痕

每次预检、数量修改、正式分配、下载、暂停、继续、失败、完成和释放都记录：

- 项目、终端和导出任务。
- 操作人和时间。
- 管理员填写数量、施工去重数量和最终需求数量。
- 同号实物数量、池补充数量、最终采集器号。
- 原采集器号、最终采集器号和是否为额外采集器。
- 采集器照片来源：盘点同号、终端表计组、池内照片或无照片。
- 预检异常中文描述及冲突表号、模块号、终端号。
- 每个文件的来源照片 ID、OSS bucket/key 摘要、相对路径、字节数、SHA256、状态和重试次数。
- 任务下载总字节、完成文件数、失败文件数和最终状态。
- 取消与释放的操作者、原因、时间和释放采集器号。

审计不得保存 OSS 永久密钥、签名 URL 或浏览器本地绝对路径。

## 12. 错误处理

- 模块号重复或一表多模块：阻止所有受影响终端，显示完整中文冲突，不自动选择“正确”模块。
- 未关闭模块类异常：阻止对应终端；异常关闭或数据修正后重新预检。
- 必需字段或表计照片缺失：阻止对应终端，其他正常终端继续。
- 采集器照片缺失：继续导出，不生成该照片，记录无照片状态。
- 采集器池不足：整批不分配、不下载，显示总缺口和分终端缺口。
- 分配并发冲突：事务回滚，整批返回重新预检，不产生部分新占用。
- OSS 内网读取失败：当前文件有限次重试后将终端标记失败，保留预留和已完成文件。
- OSS 对象大小或 SHA256 不符：不把文件标记完成，停止该终端并记录证据。
- 本地文件无权限或磁盘空间不足：停止后续下载，保留进度和预留，由管理员处理后继续。
- 浏览器不支持 File System Access API：禁止正式导出并提示使用最新版 Windows Chrome 或 Edge。
- 服务器重启：任务恢复为暂停或可恢复失败，全局租约按超时回收，采集器预留保持不变。
- 源数据在预检或下载期间变化：未锁定时拒绝旧预检；已锁定但尚未完成的相关终端进入 `needs_recheck`，不静默混用新旧资料。

## 13. 安全边界

- 只允许管理员访问任务派发页导出控件和新接口；后端必须独立鉴权，不能依赖前端隐藏。
- 所有终端、资料组、照片、异常和采集器查询均强制限定当前项目，防止跨项目读取。
- 本功能只读 OSS 对象，不覆盖、移动或删除 OSS 文件。
- 不修改施工原始表号、模块号、采集器号、照片分类或异常历史；替换关系只存在于导出分配记录和导出结果中。
- 本功能不恢复 `/exports`、旧导出任务接口或交付包 worker。
- 本地目录由浏览器直接授权，服务器不能获得或保存管理员电脑的本地路径权限。

## 14. 自动化测试与验证

### 14.1 后端测试

- 未施工资料不参与任何模块、字段、照片或采集器校验，也不进入清单。
- 部分施工终端只输出已施工资料；完全未施工终端不可导出。
- 同一资料组两张照片不会被误算成两个模块。
- 同一模块号出现在两个有效已施工资料组时，所有相关终端被阻止。
- 同一表号对应两个不同模块号时，所有相关终端被阻止。
- 冲突发生在不同终端时仍能被项目级预检发现。
- 已关闭模块异常不阻止；未关闭模块异常阻止。
- 表号、模块号、地址和两张必需照片的缺失规则准确。
- 采集器照片缺失不阻止、不产生资料异常。
- 最终数量使用 `max（施工采集器号去重数量，管理员填写数量）`。
- 同号实物优先、池随机补充、额外采集器和一对一占用正确。
- 重复导出复用分配；并发请求不能重复消费同一采集器。
- 池不足整批不落新分配；失败保留预留；只有未完成终端可取消释放。
- 照片来源优先级和稳定选择正确。
- 项目、角色和全局单任务租约隔离正确。
- 源数据版本变化触发重新预检。

### 14.2 前端测试

- 只有管理员在任务派发页看到勾选、数量输入、单终端导出和批量导出。
- 施工员界面和权限无变化。
- 卡片按优先施工、完成率、终端号排序。
- 全选只覆盖当前筛选结果。
- 预检中文错误能准确显示冲突表号、模块号和终端号。
- 批量任务按终端串行，进度、预计时间、暂停、继续和失败重试正确。
- File System Access API 写入目录结构、照片原扩展名和两个 Excel 正确。
- 断点恢复会校验并跳过已完成文件，不覆盖或重复下载。
- 不支持的浏览器被明确阻止。

### 14.3 静态与回归门禁

- 旧 `/exports` 和旧导出中心仍保持退休契约。
- 新接口不调用旧 ZIP、最终交付包或 delivery worker 构建链路。
- 服务端实现不写临时交付文件、不生成 ZIP、不缓存完整照片。
- 前端类型检查、组件测试和生产构建通过。
- 后端相关测试和完整测试通过。
- Vue 迁移门禁、权限门禁、任务派发页面和施工采集回归通过。

## 15. 验收标准

只有同时满足以下条件，才能报告功能完成：

1. 管理员可在任务派发页设置应还采集器数量、单选或批量选择终端并选择本地文件夹。
2. 未施工资料既不校验也不导出；部分施工终端只输出已施工资料。
3. 项目级模块重复和一表多模块都能拦截全部受影响终端，并显示中文冲突原因。
4. 每个导出表计具备表号、地址、模块号、“模块与电能表”和“改造后”照片。
5. 采集器照片缺失不阻止导出、不计异常。
6. 最终采集器数量、同号优先、池补充、一对一占用、复用和释放规则全部正确。
7. 目录、文件名、`终端资料.xlsx` 和有条件生成的 `补充采集器.xlsx` 符合本设计。
8. 服务器只通过 OSS 内网逐文件流式读取，公网约 `2 Mbps` 限速，不落盘、不生成 ZIP，全系统仅一个正式导出任务。
9. 暂停、继续、浏览器断开恢复和已校验文件跳过有效。
10. 审计能追溯操作者、数量、分配、照片来源、文件字节、状态、重试和释放。
11. 施工端、审阅与翻拍、数据中台、项目驾驶舱和旧导出退休保护均无回归。

## 16. 版本与发布边界

规格文档提交不提升应用版本、不发布生产。实施若仍直接基于 `V3.2.26` 且没有更晚生产版本，目标版本为 `V3.2.27`；如果实施前生产基线已经推进，则按当时生产 patch 版本加一确定目标版本。

本功能涉及数据库新增、核心导出主流程和采集器占用规则。开发完成后不能仅凭自动测试直接发布，必须先完成数据库迁移方案、备份、dry-run、回滚方案、浏览器真实目录写入验收、3 Mbps 带宽下的压力验证和用户单独生产发布确认。发布不得覆盖生产 `.env`、数据库、`data`、`uploads` 或 OSS 原对象。
