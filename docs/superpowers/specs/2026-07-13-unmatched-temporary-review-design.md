# 扫码未匹配临时审阅设计

## 目标

管理员或审阅员可以从项目驾驶舱的“扫码未匹配”清单逐条打开照片，在未确定终端前完成照片分类、扫码/OCR、人工确认和编号修正。只有管理员最终匹配总清单并确认终端后，记录才转为正式资料组。

## 核心约束

- 临时审阅期间不创建正式 `groupId`，不创建终端任务，也不使用 `00000000` 或其他占位终端。
- 临时记录不进入施工完成量、审阅完成量、KPI、归档数量和驾驶舱条码准确率。
- 匹配成功前，所有修改都保存在服务器并写入审计记录，不能只保存在浏览器。
- 匹配成功时，照片分类、扫码/OCR结果、人工确认信息和操作历史必须迁移到正式资料组。
- 匹配失败、候选不唯一或保存失败时，未匹配记录继续保留，不产生半成品资料组。
- “扫码未匹配”清单继续按每页 20 条展示。

## 角色权限

| 操作 | 管理员 | 审阅员 | 施工员 |
| --- | --- | --- | --- |
| 查看临时审阅详情和照片 | 允许 | 允许 | 禁止 |
| 修改编号、照片分类、重新扫码/OCR | 允许 | 允许 | 禁止 |
| 临时人工确认 | 允许 | 允许 | 禁止 |
| 匹配总清单并确定终端 | 允许 | 禁止 | 禁止 |

权限由服务端校验；前端隐藏或禁用按钮不作为权限控制。

## 数据模型

未匹配记录继续作为唯一业务主体，不提前写入正式资料组表。在未匹配记录的 `raw_data` 中增加版本化的 `temporary_review` 数据：

```json
{
  "version": 1,
  "state": "pending",
  "meter_no": "",
  "collector": "",
  "module_asset_no": "",
  "manual_confirmed": false,
  "reviewer": "",
  "reviewed_at": "",
  "updated_at": "",
  "photos": [
    {
      "id": "",
      "source_url": "",
      "category": "",
      "barcode_check_status": "",
      "barcode_check_values": [],
      "barcode_check_ocr_values": [],
      "barcode_check_method": "",
      "barcode_checked_at": "",
      "barcode_check_error": ""
    }
  ]
}
```

照片 ID 由未匹配记录 ID、照片顺序和源地址摘要稳定生成，保证刷新后仍能定位同一张照片。`version` 用于并发保存校验；旧版本保存返回 `409`，避免两个管理员互相覆盖。

临时人工确认只表示审阅员确认当前照片和录入值可用于后续匹配，不直接形成正式“扫码通过”。最终匹配成功后，服务端以正式资料组的表号、模块号和采集器号重新计算条码结果；通过后才计入驾驶舱准确率。

## 服务端接口

新增未匹配临时审阅接口，继续放在现有 `/local-test/unmatched` 业务边界内：

| 接口 | 作用 |
| --- | --- |
| `GET /local-test/unmatched/{id}/review` | 返回未匹配记录、稳定照片列表和临时审阅状态 |
| `PATCH /local-test/unmatched/{id}/review` | 保存表号、采集器号、模块号、分类和审阅状态 |
| `POST /local-test/unmatched/{id}/photos/{photo_id}/rescan` | 对单张照片执行现有条码、二维码和 OCR 识别链 |
| `POST /local-test/unmatched/{id}/barcode/manual-confirm` | 保存临时人工确认和审计信息 |
| `GET /local-test/unmatched/{id}/match-candidates` | 根据修正后的编号返回总清单候选及终端 |
| `POST /local-test/unmatched/{id}/finalize-match` | 管理员确认候选后原子化生成或并入正式资料组 |

候选匹配以标准化表号精确匹配为首要条件，模块号和采集器号只用于辅助排序和冲突提示。唯一候选也需要管理员确认；多个候选必须人工选择；零候选不允许提交终端。

`finalize-match` 必须在同一服务端事务中完成候选复核、资料组创建或并入、照片及审阅结果迁移、未匹配记录状态更新和审计写入。任一步失败则整体回滚。

## 前端交互

- 未匹配清单中的整行和“审阅”按钮都可打开临时审阅弹窗；行内“换表”“删除”等操作阻止行点击冒泡。
- 弹窗沿用审阅工作台的图片交互：主图、照片切换、双击放大、四类分类、重新扫码/OCR、人工确认和编号编辑。
- 弹窗不展示缩略图网格图片，使用稳定尺寸的照片序号切换，单张打开后加载原图，避免清单初次加载大量图片。
- 保存成功后更新当前记录和列表状态；关闭再打开时从服务器恢复。
- “完成审阅并匹配清单”先保存当前修改，再打开候选终端列表。管理员确认后调用 `finalize-match`。
- 匹配成功后关闭临时审阅弹窗、从未匹配清单移除该记录并刷新驾驶舱缓存；不自动跳转页面。
- 手机端弹窗改为全屏布局，主图和表单纵向排列；所有按钮和文字保持不重叠。

## 图片与识别

照片继续通过现有受控图片读取接口加载，前端使用鉴权请求生成对象 URL，不直接依赖可能过期的 OSS 地址。重新扫码复用现有旋转、增强、条码、二维码和 OCR 识别链，不在前端执行识别。

单张图片识别失败只更新该图片的错误状态，不阻断其他照片审阅。源图片不可访问时显示明确失败状态，并允许关闭后继续处理其他记录。

## 审计

以下操作分别记录操作人、时间、未匹配记录 ID、版本和变更前后值：

- 修改表号、采集器号或模块号。
- 修改照片分类。
- 重新扫码/OCR及识别结果。
- 临时人工确认或撤销确认。
- 查看候选并最终选择终端。
- 创建正式资料组或并入既有资料组。

最终资料组保留来源未匹配记录 ID，便于从正式资料组追溯整个临时审阅过程。

## 错误处理

- 记录已被其他人处理或删除：返回 `404`，关闭弹窗并刷新清单。
- 版本冲突：返回 `409`，保留本地未提交值并提示重新加载最新记录。
- 图片读取或识别失败：只标记当前图片失败，不覆盖已有分类和编号。
- 候选为零或多条但未选择：禁止最终提交。
- 最终匹配事务失败：未匹配记录和正式资料组均保持原状。
- 会话过期：沿用全局登录失效处理，任何操作返回认证失败后跳转登录页。

## 测试策略

先补测试，再修改实现。至少覆盖：

1. 打开临时审阅不会创建资料组、任务或占位终端。
2. 临时审阅不改变完成量、KPI、归档数和条码准确率。
3. 分类、编号、扫码/OCR和人工确认可保存并在重新加载后恢复。
4. 审阅员可以保存临时审阅，但不能最终匹配终端。
5. 施工员不能读取或修改临时审阅。
6. 并发版本冲突返回 `409`，不会覆盖新数据。
7. 零候选和未选择的多候选不能生成资料组。
8. 匹配成功后正确创建或并入资料组，并迁移照片分类和识别结果。
9. 最终匹配任一步失败时完整回滚，未匹配记录仍可继续审阅。
10. 临时人工确认不计入准确率，正式匹配并重新校验通过后才计入。
11. 前端行点击和“审阅”按钮可打开对应记录，换表和删除不会误开弹窗。
12. 未匹配清单保持每页 20 条，弹窗关闭后回到原页。
13. 图片通过鉴权对象 URL 加载，失败时显示错误状态并可切换下一张。

完成聚焦测试后运行完整后端测试、前端测试、TypeScript检查、前端生产构建、安全校验和发布SOP校验。

## 版本与发布

本功能按生产小更新从 `V3.0.79` 升级到 `V3.0.80`，更新内容使用中文。发布前执行独立代码审阅、生产数据和配置备份；发布后执行健康检查、权限矩阵验证、临时审阅页面验证、匹配迁移验证和服务器最近五个版本保留检查。

## 不在本次范围

- 批量审阅或批量匹配未匹配记录。
- 自动选择终端或在无候选时创建占位终端。
- 修改现有施工端上传和自动上传策略。
- 改变正式资料组的 KPI、条码准确率或自动归档规则。
