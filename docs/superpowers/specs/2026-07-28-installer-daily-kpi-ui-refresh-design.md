# 安装人员每日工作量 KPI 弹窗 UI 改版设计

## 1. 状态

- 日期：2026-07-28
- 设计状态：用户已选定
- 总体方向：A「经营简报」
- 第二层指标方向：A1「通栏简报」
- 目标组件：`v2-web/src/components/InstallerKpiDialog.vue`

## 2. 背景

V3.2.1 已恢复安装人员每日工作量 KPI 弹窗。当前功能完整，但七项汇总指标权重相同、弹窗首屏较拥挤，超宽明细表的阅读层级也不清楚。

本次只改造弹窗的视觉和布局，不改变用户熟悉的 KPI 模式、字段、筛选、下钻和导出能力。

## 3. 目标

1. 管理人员打开弹窗后，先看到最重要的产出、归档和异常信息。
2. 用第二层指标带呈现工时和完成效率，与第一层主指标形成清楚层级。
3. 保留全部每日明细字段，同时改善表头、列宽、横向滚动和重点数据辨识。
4. 保持原始资料入口、CSV 导出、工时分段、地址明细和异常明细能力不变。
5. 在常用桌面分辨率下减少拥挤、裁切和无效留白。

## 4. 非目标

- 不修改 KPI 公式、归属规则或统计口径。
- 不修改后端 API、数据库结构或生产数据。
- 不修改项目驾驶舱主页面的视觉布局。
- 不删除现有明细字段、下钻能力或导出字段。
- 不新增趋势图、排行榜、筛选器或新的业务功能。

## 5. 视觉语言

这是面向生产管理人员的 B2B 经营简报界面。

- 背景以白色和冷灰为主。
- 主文字使用深蓝黑，次级文字使用中性灰蓝。
- 仅用克制的业务蓝强调关键数字、焦点和主要操作。
- 弱化大面积阴影和重复圆角卡片，主要依靠字号、间距、分隔线和浅色底建立层级。
- 异常继续使用现有语义色，不以装饰性色替代业务状态。
- 动效只保留弹窗和现有交互所需的轻量反馈，并尊重减少动态效果设置。

## 6. 弹窗结构

### 6.1 标题区

标题区显示：

- 人员姓名；
- “每日工作量”标题；
- 当前统计范围；
- 关闭按钮。

不新增无数据来源的更新时间或状态标签。

### 6.2 第一层主指标

第一层固定为四项：

1. 资料组；
2. 照片；
3. 已归档；
4. 异常。

四项使用等宽布局。每项由小号标签和大号数字构成，配合浅灰底和细蓝色左侧强调线。异常值沿用现有异常语义色，但不把整块背景染红。

### 6.3 第二层 A1 通栏简报

第二层固定为：

1. 总工时；
2. 完成量；
3. 加权完成。

三项放在同一条浅蓝灰信息带内，不拆成三张独立卡片。

- 三项等宽排列；
- 项目之间使用一像素竖向分隔线；
- 总工时使用业务蓝作为主要强调值；
- 完成量和加权完成使用深色粗体；
- 信息带上下各有一像素边界；
- 不使用独立阴影、图标、进度条或装饰徽章。

桌面端保持单行。窄屏下允许改为两列或单列，但必须保持标签和值的对应关系。

### 6.4 每日明细表

每日明细表保留现有全部列和交互。

- 表头固定；
- 日期列固定在左侧；
- 常用字段放在现有顺序的前部，不改变字段含义；
- 有效工时继续使用业务蓝强调；
- 数值列统一右对齐或按现有组件的数值对齐方式保持一致；
- 表格区域独立纵向滚动；
- 超出宽度时使用清晰的横向滚动，不压缩到不可读；
- 行悬停只提供轻微底色反馈；
- 下钻入口、异常入口和工时分段入口保持原行为。

### 6.5 底部操作区

底部保留：

- 关闭；
- 查看原始资料；
- 导出 KPI CSV。

“导出 KPI CSV”为主要按钮，“查看原始资料”为次要按钮，“关闭”为低强调按钮。按钮文案、权限、参数和行为不变。

## 7. 组件与数据边界

本次改造继续使用现有 `InstallerKpiDialog.vue`、`InstallerWorkload` 数据和 `installerKpi.ts` 纯逻辑。

- 父页面继续通过 `v-model`、`installer` 和 `scope` 控制弹窗。
- 弹窗继续调用现有 `fetchInstallerWorkload`。
- 所有筛选、分页、下钻和 CSV 生成逻辑保持不变。
- UI 改造只重排现有汇总值和明细表容器。
- 如重复的指标标记影响可读性，可在组件内部增加仅负责呈现的小型计算结构，但不得复制 KPI 计算逻辑。

没有新增网络请求、写接口、缓存策略或全局状态。

## 8. 状态处理

- 加载：保留局部加载，不阻塞项目驾驶舱。
- 空数据：保留明确空状态，隐藏不可用导出操作。
- 请求失败：保留错误提示和关闭后重试能力。
- 快速切换人员：继续防止旧响应覆盖当前人员。
- 无异常或无工时分段：对应下钻入口保持不可用或不显示。
- 横向滚动：不能遮挡底部操作区或弹窗关闭按钮。

## 9. 响应式与可访问性

- 1440×900 和 1366×768 下，弹窗主信息与至少数行明细应同时可见。
- 1024 像素宽度下不允许正文溢出弹窗；明细表使用内部横向滚动。
- 第一层在窄屏可从四列降为两列。
- 第二层在窄屏可从三列降为一列或两列。
- 交互元素保留键盘焦点样式和可识别的悬停状态。
- 颜色不作为异常、选中或禁用状态的唯一提示。

## 10. 验收与测试

### 10.1 功能回归

1. 打开和关闭每日工作量 KPI 弹窗。
2. 切换全部、日、周、月范围后数据一致。
3. 每日明细、工时分段、地址和异常下钻仍可用。
4. 查看原始资料仍携带当前人员和日期范围。
5. CSV 导出字段、内容和文件名不变。
6. 加载、空数据、错误状态和快速人员切换行为不变。

### 10.2 视觉验收

1. 第一层四项主指标比第二层三项辅助指标更突出。
2. 第二层实现 A1 通栏样式，不出现三张独立卡片。
3. 有效工时和主要操作使用统一业务蓝。
4. 表头、日期列、横向滚动和底部操作区不发生遮挡。
5. 1440×900、1366×768 和 1024 像素宽度下无裁切、重叠或不可读压缩。

### 10.3 工程验证

- 现有 KPI 纯逻辑测试；
- KPI 恢复门禁脚本；
- 前端类型检查；
- 前端生产构建；
- 浏览器桌面和窄屏截图对比；
- 生产发布前的现有版本、包完整性和健康检查门禁。

## 11. 发布边界

改动属于前端视觉调整。发布使用新的版本化 release，不覆盖当前 release，不修改 `.env`、上传文件、缓存、数据库或生产业务数据。上线前后使用同一名安装人员和同一统计范围对比所有 KPI 数值，确认只有布局和样式变化。
