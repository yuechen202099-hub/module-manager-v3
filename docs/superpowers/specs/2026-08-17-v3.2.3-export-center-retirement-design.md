# V3.2.3 导出中心下线与 OSS 本地导出设计

## 1. 决策与目标

用户于 2026-08-17 确认下线生产系统导出中心。生产系统不再向网页用户提供批量业务导出，也不再在服务器上生成最终交付 ZIP、Excel、CSV 或交付包缓存。后续需要导出时，由 Codex 按用户给定的项目、终端、范围和本地目录执行只读导出：服务器只提供结构化元数据或短期签名信息，文件内容直接从 OSS 下载到用户电脑，压缩、Excel/CSV 生成和校验全部在本机完成。

本次应用版本从 `V3.2.2` 推进到 `V3.2.3`。紧急 Nginx 拦截是 V3.2.3 发布前的临时安全措施；正式版本上线后仍保留后端拒绝逻辑，防止旧页面、浏览器缓存或直接 API 请求恢复导出链路。

## 2. 生产证据与根因

2026-08-17 的只读生产检查确认：

- 服务器总内存约 `1.6 GiB`，检查时可用内存约 `460 MiB`。
- FastAPI API 常驻内存约 `382 MiB`，条码维护 worker 常驻内存约 `147 MiB`。
- Linux 日志记录 API 进程在 2026-07-26、07-27、07-28、07-29、07-31、08-04、08-08 和 08-16 多次被 OOM killer 杀死。
- 2026-08-17 11:41:57 用户打开 `/exports`，11:42:01 `/exports/terminal-readiness?page=1&page_size=20&query=` 返回 `499`，该次启动随后终止，服务器在 12:16 重启。
- 当前生产库包含 `22,358` 个资料组、`16,361` 张有效照片；终端就绪查询形成 `34,617` 行联表结果。
- `PostgresStateRepository._export_center_lightweight_groups()` 先读取所有命中资料组及有效照片的 `raw_data`，在 Python 中组装全部对象后才分页。打开导出中心即可触发此路径，不需要真正创建导出任务。
- 检查时 `export_jobs` 和 `delivery_package_jobs` 均为 `0` 行。因此此次故障点是导出中心的全量就绪查询，不是一个已经成功创建的导出任务。

结论：只隐藏“下载”按钮不足以保护服务器。必须同时下线页面、查询接口、创建/下载接口和后台交付包生成链路。

## 3. 范围

### 3.1 下线内容

- 主导航中的“导出中心”。
- Vue 路由 `/exports`、`ExportsView.vue` 及其导出中心组件入口。
- `/exports/*` 下的目录、任务选项、终端就绪、创建任务、任务列表、下载、任务详情、最终交付、异常表计、项目外施工等全部接口。
- `/local-test/export-manifest/final-delivery`、`/local-test/unmatched/export`、`/local-test/photo-barcode/review-groups/export` 等遗留批量导出接口。
- 项目驾驶舱、数据中台、任务页和其他业务页面中的批量导出按钮，包括浏览器本地生成的 KPI CSV。
- 自动归档或资料修改后自动排队生成交付包缓存的链路。
- 条码维护 worker 对 `delivery_package` 任务的领取和 ZIP 构建；worker 的条码扫描、缓存校验和其他非导出职责继续运行。

### 3.2 保留内容

- PostgreSQL 中的业务数据、历史审计、`export_jobs` 和 `delivery_package_jobs` 表结构及历史行。
- OSS 中的生产原图和现有对象，禁止本次任务修改或删除。
- 现有导出格式规则和构建器源码，作为本机导出实现的格式参考，但不得保留任何可从生产 HTTP 或后台 worker 调用的入口。
- 单张照片预览、审阅和正常施工上传。
- 导入模板下载，因为它属于导入辅助资料，不是业务数据导出。
- 数据中台、项目驾驶舱、KPI 查询和其他只读页面功能；仅移除其中的导出动作。

## 4. 方案比较

### 4.1 仅隐藏前端入口

改动最少，但旧浏览器缓存、书签和直接 API 请求仍能触发全量查询或创建任务，不能解决生产风险，不采用。

### 4.2 两阶段完整下线

先由 Nginx 拦截已知危险路径，再通过 V3.2.3 永久移除前端入口、拒绝后端请求并停止后台交付包生成。该方案能立即止血，发布后也有应用级保护；保留数据和源码便于审计与本地格式复用。采用此方案。

### 4.3 删除全部导出代码、表和缓存

会引入数据库迁移、历史审计丢失和大范围回归风险，也不利于本地导出复用，不采用。

## 5. 阶段一：生产 Nginx 紧急拦截

### 5.1 操作边界

紧急操作只修改当前生效的 Module Manager Nginx 站点配置，不修改应用 release、`.env`、PostgreSQL、OSS、`data`、`uploads` 或系统服务定义。

执行前必须：

1. 用 `nginx -T` 确认实际生效配置文件。
2. 将该文件复制为同目录、带 UTC 时间戳的备份。
3. 记录修改前文件 SHA256。

增加精确或前缀拦截，使以下请求不再进入 Uvicorn：

- `/exports`
- `/exports/*`
- `/local-test/export-manifest/final-delivery`
- `/local-test/unmatched/export`
- `/local-test/photo-barcode/review-groups/export`

响应使用 HTTP `410 Gone`，不得代理到应用。配置修改后先执行 `nginx -t`，仅在成功时 reload；`nginx -t` 失败时恢复备份，不 reload。

### 5.2 紧急验收

- 上述路径返回 `410`。
- `/health`、`/project-board`、`/construction` 和常用只读 API 仍可访问。
- `module-manager-v2.service` 和 `module-manager-v2-photo-barcode-maintenance.service` 保持 `active`。
- Uvicorn 日志中不再出现新的 `/exports/terminal-readiness` 请求。

### 5.3 紧急回滚

恢复备份文件，执行 `nginx -t`，成功后 reload。回滚不得重启 PostgreSQL、应用或 worker。

## 6. 阶段二：V3.2.3 永久下线

### 6.1 前端

- 从主导航和路由表删除导出中心。
- 删除其他业务页面的批量导出按钮及调用代码；保留查询、筛选和展示。
- 旧书签访问 `/exports` 时由服务器返回 `410`，不重定向到可能继续发请求的旧页面。
- 不再构建或加载导出中心异步 chunk。
- 前端不得调用 `/exports/terminal-readiness`、`/exports/jobs`、`/exports/final-delivery` 或任何遗留导出接口。

### 6.2 后端 HTTP

- 所有 `/exports` 和 `/exports/*` 请求在读取 repository、执行 SQL 或访问文件前返回 `410`。
- 遗留批量导出接口同样在进入业务逻辑前返回 `410`。
- 返回固定中文说明：`导出中心已下线，请联系管理员由 OSS 导出到本机。`
- 权限校验不能替代下线保护；管理员、施工员、匿名用户和旧 token 都不能进入导出业务逻辑。
- 保留接口实现源码时，路由层必须有单一、可测试的总开关或拒绝依赖，避免漏拦某个处理函数。

### 6.3 后台任务

- 自动归档、照片分类、条码人工确认、资料组修改等流程不得再创建或刷新交付包缓存任务。
- `_enqueue_delivery_cache_after_commit`、`_stage_data_center_auto_archive_delivery_jobs`、`_json_request_data_center_delivery_package` 和直接最终交付请求均不得产生新 `delivery_package_jobs`。
- worker 不再领取或处理 `delivery_package` 类型任务，不调用 `build_final_delivery_export()`；条码识别和其他维护任务不受影响。
- 部署前重新只读检查 `delivery_package_jobs`。若出现待处理行，停止发布并单独向用户申请数据状态处理授权；本次设计不删除、不取消、不改写生产任务行。

### 6.4 数据与存储

- 无数据库迁移。
- 不清理历史导出表、历史审计或现有本地缓存。
- 不修改和不删除任何 OSS 对象。
- 发布包不得包含 `.env`、密钥、数据库 dump、真实上传、交付缓存或本地导出文件。

## 7. OSS 到本机的后续导出流程

用户每次提出导出时提供：项目或团队、终端/资料组范围、是否只包含已归档资料、输出格式和本地目录。未指定目录时使用：

`C:\Users\Administrator\Downloads\module-manager-exports\<YYYYMMDD-HHmmss>`

Codex 按以下步骤执行：

1. 通过 SSH 对 PostgreSQL 执行只读事务，只查询所需资料组、字段、照片 OSS key、文件名、分类和 SHA256；不把数据库凭据输出到终端或文件。
2. 在小批次内生成原图短期签名 URL，或使用只读、短期 OSS 凭据；服务器只做签名和元数据查询，不代理图片字节。
3. 用户电脑直接从 OSS 下载文件。下载并发默认不超过 `4`，失败采用有上限的退避重试，避免打满本机或 OSS 链路。
4. 在本机按现有分类和命名规则生成目录、ZIP、Excel 或 CSV。
5. 校验计划数量、成功数量、失败数量、文件大小和可用 SHA256；保留失败清单，不用空文件或占位文件伪装成功。
6. 向用户报告本地绝对路径、范围、文件数量、失败项、重复项、校验结果和生成时间。

OSS 下载必须是只读操作。任何 OSS 写入、覆盖、移动或删除均不属于本流程，必须重新取得用户明确授权。

## 8. 错误处理

- Nginx 配置校验失败：恢复备份，不 reload。
- V3.2.3 路由遗漏：发布门禁失败，不打包、不部署。
- 后台仍产生交付包任务：发布门禁失败，定位调用方后再继续。
- OSS 对象不存在、签名失效或哈希不符：在本机导出报告中列为失败，不回写生产库，不修改 OSS。
- 本机磁盘空间不足：生成文件前停止，报告预计体积和所需空间。
- 部分下载失败：保留已成功文件与清单，不宣称完整导出；用户可选择只重试失败项。

## 9. 测试与验收

### 9.1 自动化测试

- 路由测试证明 `/exports`、`/exports/*` 和遗留导出接口统一返回 `410`。
- 使用会在访问时失败的 repository 替身，证明拒绝发生在 repository/SQL/文件访问之前。
- 前端路由、导航和构建产物中不存在导出中心入口。
- 页面测试证明项目驾驶舱、数据中台、任务页和 KPI 页面不显示批量导出按钮。
- 后台测试证明自动归档、照片分类、条码人工确认和资料修改不会创建交付包任务。
- worker 测试证明不会领取或处理 `delivery_package`，但条码任务仍正常处理。
- 本机 OSS 导出测试使用假 OSS 对象验证目录结构、命名、重试、失败清单、数量和 SHA256，不接触生产 OSS。

### 9.2 发布前门禁

- 相关后端测试、完整后端测试、前端类型检查和生产构建通过。
- `verify_v3_2_0_export_center_ui.py` 和 `verify_v3_2_0_single_export_entry.py` 更新为“导出中心已退休”契约，不能简单删除门禁。
- 新增静态门禁，禁止生产前端重新引用 `ExportsView`、`fetchExportCatalog`、`fetchTerminalDeliveryReadiness`、`createExportJob` 或下载函数。
- 发布包独立验包，确认不包含密钥、`.env`、数据、上传、缓存和本机导出产物。

### 9.3 生产验收

- 先确认 Uvicorn 监听 `127.0.0.1:8000`，再做页面/API 验证。
- `/exports`、`/exports/terminal-readiness`、`/exports/jobs`、`/exports/final-delivery` 和遗留导出接口返回 `410`。
- `/project-board`、`/global-search`、`/claim-tasks`、`/construction`、健康接口和 KPI 查询正常。
- 生产日志中没有导出 SQL、ZIP 构建或 `delivery_package` worker 处理记录。
- 生产库只读确认发布后未新增 `export_jobs` 或 `delivery_package_jobs`。
- 记录 API/worker 内存、服务状态、发布包 SHA256、release 路径和回滚目标。

## 10. 发布与回滚

V3.2.3 使用新的 `production/V3/3.2.3` 维护分支和版本化 release。发布前备份 `.env`、PostgreSQL、`data`、`uploads` 和当前 release，校验备份及发布包 SHA256。切换后等待 Uvicorn 端口就绪，再执行完整生产验收。

应用回滚恢复到 V3.2.2 release，但默认保留 Nginx 的 `/exports` 紧急拦截，避免旧版本重新暴露危险入口。只有用户明确要求恢复网页导出且已提供新的性能安全设计时，才允许移除 Nginx 拦截。

服务器 release 清理必须先 dry-run，只保留最近五个可回滚 release，不得触碰 `.env`、`data`、`uploads`、`backups`、数据库 dump 或 OSS。

## 11. 验收结论标准

只有同时满足以下条件，才能报告“导出中心已下线”：

1. Nginx 和应用层均阻止旧导出入口。
2. 打开任何现存业务页面不会触发导出中心查询。
3. 后台不会生成最终交付 ZIP 或交付包缓存。
4. 条码扫描、施工、审阅、数据中台、驾驶舱和 KPI 查询无回归。
5. 未修改生产 PostgreSQL 数据和 OSS 对象。
6. 已验证一条假 OSS 到本机的导出流程，并能输出数量、失败清单和 SHA256。
7. 发布记录包含备份、哈希、回滚、服务状态、内存和线上接口证据。
