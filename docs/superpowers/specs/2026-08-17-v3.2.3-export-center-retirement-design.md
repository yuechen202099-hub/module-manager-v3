# V3.2.3 导出中心下线与 OSS 本地导出设计

## 1. 决策与目标

用户于 2026-08-17 确认下线生产系统导出中心，并于 2026-08-18 确认将有效的外链照片迁入 OSS。生产系统不再向网页用户提供批量业务导出，也不再在服务器上生成最终交付 ZIP、Excel、CSV 或交付包缓存。V3.2.3 先停止旧导出链路，再以独立、低资源、可恢复的迁移工具将有效的 `external_url` 照片写入 OSS；后续需要导出时，由 Codex 按用户给定的项目、终端、范围和本地目录执行导出：服务器只提供结构化元数据或短期签名信息，文件内容直接从 OSS 下载到用户电脑，压缩、Excel/CSV 生成和校验全部在本机完成。

本次应用版本从 `V3.2.2` 推进到 `V3.2.3`。紧急 Nginx 拦截是 V3.2.3 发布前的临时安全措施；正式版本上线后仍保留后端拒绝逻辑，防止旧页面、浏览器缓存或直接 API 请求恢复导出链路。

## 2. 生产证据与根因

2026-08-17 的只读生产检查确认：

- 服务器总内存约 `1.6 GiB`，检查时可用内存约 `460 MiB`。
- FastAPI API 常驻内存约 `382 MiB`，条码维护 worker 常驻内存约 `147 MiB`。
- Linux 日志记录 API 进程在 2026-07-26、07-27、07-28、07-29、07-31、08-04、08-08 和 08-16 多次被 OOM killer 杀死。
- 2026-08-17 11:41:57 用户打开 `/exports`，11:42:01 `/exports/terminal-readiness?page=1&page_size=20&query=` 返回 `499`，该次启动随后终止，服务器在 12:16 重启。
- 当前生产库包含 `22,358` 个资料组、`16,361` 张有效照片；终端就绪查询形成 `34,617` 行联表结果。
- 有效照片的存储分布为 OSS `14,133` 张、`external_url` `2,002` 张、空类型或其他 `226` 张。外链照片必须先经过逐张校验和迁移，不能在本机导出时继续依赖不稳定的第三方地址。
- `PostgresStateRepository._export_center_lightweight_groups()` 先读取所有命中资料组及有效照片的 `raw_data`，在 Python 中组装全部对象后才分页。打开导出中心即可触发此路径，不需要真正创建导出任务。
- 检查时 `export_jobs` 和 `delivery_package_jobs` 均为 `0` 行。因此此次故障点是导出中心的全量就绪查询，不是一个已经成功创建的导出任务。

结论：只隐藏“下载”按钮不足以保护服务器。必须同时下线页面、查询接口、创建/下载接口和后台交付包生成链路。

## 3. 范围

### 3.1 下线内容

- 主导航中的“导出中心”。
- Vue 路由 `/exports`、`ExportsView.vue` 及其导出中心组件入口。
- `/exports/*` 下的目录、任务选项、终端就绪、创建任务、任务列表、下载、任务详情、最终交付、异常表计、项目外施工等全部接口。
- `/local-test/export-manifest/final-delivery`、`/local-test/unmatched/export`、`/local-test/photo-barcode/review-groups/export` 等遗留批量导出接口。
- 项目驾驶舱、数据中台、任务页和其他业务页面中的批量导出按钮，包括浏览器本地生成的 KPI CSV。
- 自动归档或资料修改后自动排队生成交付包缓存的链路。
- 条码维护 worker 对 `delivery_package` 任务的领取和 ZIP 构建；worker 的条码扫描、缓存校验和其他非导出职责继续运行。

### 3.2 保留内容

- PostgreSQL 中的业务数据、历史审计、`export_jobs` 和 `delivery_package_jobs` 表结构及历史行。
- OSS 中已有的生产原图和现有对象；外链迁移允许新增内容地址对象，但禁止覆盖、移动或删除任何已有对象。
- 现有导出格式规则和构建器源码，作为本机导出实现的格式参考，但不得保留任何可从生产 HTTP 或后台 worker 调用的入口。
- 单张照片预览、审阅和正常施工上传。
- 导入模板下载，因为它属于导入辅助资料，不是业务数据导出。
- 数据中台、项目驾驶舱、KPI 查询和其他只读页面功能；仅移除其中的导出动作。

### 3.3 外链迁移范围

- 仅迁移 `photos.is_active = true` 且 `storage_type = 'external_url'` 的照片；软删除照片不属于后续导出范围。
- 新增独立命令行工具 `v2-api/scripts/migrate_external_photos_to_oss.py`，不得暴露 HTTP 路由，也不得由常驻 worker 自动启动。
- 迁移新增 OSS 对象，并在校验成功后更新对应照片的存储字段和审计字段；不删除原外链、不删除 OSS 对象。
- 空存储类型和其他未知类型的 `226` 张照片不自动归类为外链；它们必须在预检报告中单列，未经来源确认不得迁移或改写。

## 4. 方案比较

### 4.1 仅隐藏前端入口

改动最少，但旧浏览器缓存、书签和直接 API 请求仍能触发全量查询或创建任务，不能解决生产风险，不采用。

### 4.2 两阶段完整下线

先由 Nginx 拦截已知危险路径，再通过 V3.2.3 永久移除前端入口、拒绝后端请求并停止后台交付包生成。该方案能立即止血，发布后也有应用级保护；保留数据和源码便于审计与本地格式复用。采用此方案。

### 4.3 删除全部导出代码、表和缓存

会引入数据库迁移、历史审计丢失和大范围回归风险，也不利于本地导出复用，不采用。

### 4.4 服务器端低资源迁移

在服务器以独立命令行工具逐张流式下载外链照片，校验后写入 OSS，并以短事务切换 PostgreSQL 存储字段。OSS 凭据不离开服务器，内容地址 key 使重试幂等；默认单线程并设置内存、磁盘和健康停止门禁。采用此方案。

### 4.5 本机中转迁移

由用户电脑下载外链再上传 OSS，能减轻服务器网络和计算负担，但需要把 OSS 写权限带到本机，数据链路和凭据暴露面更大，不采用。

### 4.6 云端远程抓取

使用云端异步抓取能力可进一步降低服务器负载，但需要新增云端权限、任务状态和回调体系，超出一次性迁移所需范围，不采用。

## 5. 阶段一：生产 Nginx 紧急拦截

### 5.1 操作边界

紧急操作只修改当前生效的 Module Manager Nginx 站点配置，不修改应用 release、`.env`、PostgreSQL、OSS、`data`、`uploads` 或系统服务定义。

执行前必须：

1. 用 `nginx -T` 确认实际生效配置文件。
2. 将该文件复制为同目录、带 UTC 时间戳的备份。
3. 记录修改前文件 SHA256。

增加精确或前缀拦截，使以下请求不再进入 Uvicorn：

- `/exports`
- `/exports/*`
- `/local-test/export-manifest/final-delivery`
- `/local-test/unmatched/export`
- `/local-test/photo-barcode/review-groups/export`

响应使用 HTTP `410 Gone`，不得代理到应用。配置修改后先执行 `nginx -t`，仅在成功时 reload；`nginx -t` 失败时恢复备份，不 reload。

### 5.2 紧急验收

- 上述路径返回 `410`。
- `/health`、`/project-board`、`/construction` 和常用只读 API 仍可访问。
- `module-manager-v2.service` 和 `module-manager-v2-photo-barcode-maintenance.service` 保持 `active`。
- Uvicorn 日志中不再出现新的 `/exports/terminal-readiness` 请求。

### 5.3 紧急回滚

恢复备份文件，执行 `nginx -t`，成功后 reload。回滚不得重启 PostgreSQL、应用或 worker。

## 6. 阶段二：V3.2.3 永久下线

### 6.1 前端

- 从主导航和路由表删除导出中心。
- 删除其他业务页面的批量导出按钮及调用代码；保留查询、筛选和展示。
- 旧书签访问 `/exports` 时由服务器返回 `410`，不重定向到可能继续发请求的旧页面。
- 不再构建或加载导出中心异步 chunk。
- 前端不得调用 `/exports/terminal-readiness`、`/exports/jobs`、`/exports/final-delivery` 或任何遗留导出接口。

### 6.2 后端 HTTP

- 所有 `/exports` 和 `/exports/*` 请求在读取 repository、执行 SQL 或访问文件前返回 `410`。
- 遗留批量导出接口同样在进入业务逻辑前返回 `410`。
- 返回固定中文说明：`导出中心已下线，请联系管理员由 OSS 导出到本机。`
- 权限校验不能替代下线保护；管理员、施工员、匿名用户和旧 token 都不能进入导出业务逻辑。
- 保留接口实现源码时，路由层必须有单一、可测试的总开关或拒绝依赖，避免漏拦某个处理函数。

### 6.3 后台任务

- 自动归档、照片分类、条码人工确认、资料组修改等流程不得再创建或刷新交付包缓存任务。
- `_enqueue_delivery_cache_after_commit`、`_stage_data_center_auto_archive_delivery_jobs`、`_json_request_data_center_delivery_package` 和直接最终交付请求均不得产生新 `delivery_package_jobs`。
- worker 不再领取或处理 `delivery_package` 类型任务，不调用 `build_final_delivery_export()`；条码识别和其他维护任务不受影响。
- 部署前重新只读检查 `delivery_package_jobs`。若出现待处理行，停止发布并单独向用户申请数据状态处理授权；本次设计不删除、不取消、不改写生产任务行。

### 6.4 数据与存储

- 无数据库迁移。
- 不清理历史导出表、历史审计或现有本地缓存。
- 外链迁移只允许新增内容地址 OSS 对象；禁止覆盖、移动或删除已有对象。
- 外链迁移只允许更新目标照片的存储字段、内容 SHA256 和 `raw_data` 审计字段，并按证据版本规则失效对应资料组的条码验证；不得修改业务分类、归档信息或其他照片。
- 发布包不得包含 `.env`、密钥、数据库 dump、真实上传、交付缓存或本地导出文件。

## 7. 阶段三：有效外链照片迁入 OSS

阶段三只能在 V3.2.3 已停止交付缓存排队和 worker 处理后执行，避免照片证据更新重新触发服务器缓存或 ZIP 生成。

### 7.1 工具边界与命令模式

新增 `v2-api/scripts/migrate_external_photos_to_oss.py`，直接复用应用配置、SQLAlchemy 模型、OSS 客户端和远程图片安全校验器，但不注册 FastAPI 路由、不加入常驻 worker，也不由部署脚本自动执行。命令必须显式选择以下互斥模式之一：

- `--dry-run`：只读统计有效 `external_url`、来源域名、空或未知存储类型、声明哈希类别和预检失败；不下载、不上传、不写数据库。
- `--execute --migration-id <id>`：执行新迁移；支持 `--limit 10` 做生产小批量验收。
- `--resume --migration-id <id>`：跳过该批次已提交记录，重试仍为有效 `external_url` 的未完成项。
- `--rollback-run <id>`：只恢复该批次保存在 `raw_data.pre_oss_*` 中的数据库字段；不删除 OSS 对象。

`--execute` 和 `--resume` 都要求显式的来源域名白名单文件；`--rollback-run` 不访问外链或 OSS。报告默认写到服务器 release 之外的受控运维目录，文件权限为仅部署用户可读；标准输出和报告均不得包含 URL 查询参数、OSS 密钥或签名 URL。

### 7.2 资源与安全门禁

- 默认且最大下载并发均为 `1`，一次只保留一个临时文件，单张文件硬上限为 `30 MiB`。
- 启动前要求 `MemAvailable >= 400 MiB`、临时目录可用空间 `>= 512 MiB`、API 健康检查通过且没有新的 OOM 记录。
- 运行中若 `MemAvailable < 250 MiB`、API 健康检查失败、出现新 OOM 记录或 OSS 错误连续达到 `5` 次，安全停止并保留可恢复报告。
- 外链必须是无用户名和密码的 HTTP/HTTPS URL；来源主机必须在显式白名单内。下载复用 DNS 固定连接，禁止访问私有、回环、链路本地和保留地址，禁止跟随重定向，阻断 DNS 重绑定。
- 下载内容流式写入临时文件并同步计算 SHA256；必须通过 Content-Length 上限、非空、Pillow 解码和格式完整性校验。

### 7.3 OSS 写入与幂等性

OSS key 沿用内容地址规则 `oss_object_key(...)`，由团队和实际内容 SHA256 决定。同一内容重复执行得到同一个 key，不创建重复对象。上传使用文件流，不将完整图片载入 Python 内存；对象写入 `Content-Type` 和 `x-oss-meta-sha256` 元数据。

数据库切换前必须通过 OSS HEAD 验证 bucket、key、Content-Length 和 `x-oss-meta-sha256`。若进程在上传后、数据库提交前退出，恢复运行复用相同对象；由于内容地址对象可能已被其他照片引用，失败和回滚都不得自动删除它。

### 7.4 PostgreSQL 原子切换与证据版本

候选按团队、资料组和照片稳定排序，下载和 OSS 上传期间不持有数据库事务。每个资料组完成上传尝试后开启短事务，锁定资料组和准备切换的照片行，并逐张重新核对 `is_active = true`、`storage_type = 'external_url'`、原 `image_url` 和来源哈希；发生并发变化的记录标记为冲突，不覆盖新数据。

已验证照片更新以下字段：

- `image_url = 'oss://<bucket>/<key>'`
- `storage_type = 'oss'`
- `storage_bucket`、`storage_key`、`object_key`
- 实际内容 `sha256`、`content_type`、`byte_size`

`raw_data` 同时保存 `pre_oss_image_url`、`pre_oss_storage_type`、`pre_oss_storage_bucket`、`pre_oss_storage_key`、`pre_oss_object_key`、`pre_oss_sha256`、`oss_migration_id`、`oss_synced_at` 和原始来源类型。原外链保留用于审计，但不再作为业务读取地址。

历史外链照片的 `sha256` 可能是 URL 文本哈希：若原值为空、等于原 URL 的 SHA256 或等于实际内容 SHA256，允许写入实际内容 SHA256；若是其他 64 位声明哈希且与内容不符，则以 `declared_hash_mismatch` 失败，不修改数据库。

同一资料组只调用一次条码证据失效逻辑，使验证 worker 按新的内容 SHA256 重新验证。V3.2.3 的交付缓存排队函数此时必须已成为无操作，因此该失效不得创建 `delivery_cache` 或 `delivery_package` 任务。

### 7.5 试迁移、对账与完成标准

先执行 dry-run，再以 `--limit 10` 迁移十张。小批量必须验证照片预览、OSS HEAD、数据库审计字段、条码状态、API/worker 内存及零交付任务新增，全部通过后才能恢复同一批次执行全量。

全量报告至少包含：迁移前候选数、上传数、复用对象数、提交数、失败数、冲突数、实际字节数、剩余有效外链数、空或未知存储类型数和每类失败数量。只有有效照片的 `external_url` 数量为 `0` 才能报告迁移完整；否则保留失败清单并继续按批次恢复，不得将失败照片伪装为 OSS 照片。

## 8. OSS 到本机的后续导出流程

外链迁移完成后，用户每次提出导出时提供：项目或团队、终端/资料组范围、是否只包含已归档资料、输出格式和本地目录。未指定目录时使用：

`C:\Users\Administrator\Downloads\module-manager-exports\<YYYYMMDD-HHmmss>`

Codex 按以下步骤执行：

1. 通过 SSH 对 PostgreSQL 执行只读事务，确认请求范围内没有有效 `external_url` 照片；空或未知存储类型必须列为不支持项，不能伪装为完整导出。
2. 只查询所需资料组、字段、照片 OSS key、文件名、分类和实际内容 SHA256；不把数据库凭据输出到终端或文件。
3. 在小批次内生成原图短期签名 URL，或使用只读、短期 OSS 凭据；服务器只做签名和元数据查询，不代理图片字节。
4. 用户电脑直接从 OSS 下载文件。下载并发默认不超过 `4`，失败采用 `1`、`2`、`4` 秒的有上限退避重试，避免打满本机或 OSS 链路。
5. 在本机按现有分类和命名规则生成目录、ZIP、Excel 或 CSV。
6. 校验计划数量、成功数量、失败数量、文件大小和 SHA256；保留失败清单，不用空文件或占位文件伪装成功。
7. 向用户报告本地绝对路径、范围、文件数量、失败项、重复项、校验结果和生成时间。

OSS 下载必须是只读操作。任何 OSS 写入、覆盖、移动或删除均不属于本流程，必须重新取得用户明确授权。

## 9. 错误处理

- Nginx 配置校验失败：恢复备份，不 reload。
- V3.2.3 路由遗漏：发布门禁失败，不打包、不部署。
- 后台仍产生交付包任务：发布门禁失败，定位调用方后再继续。
- 外链来源主机不在白名单、解析到禁用地址、发生重定向或 DNS 重绑定：该照片失败，不下载、不上传、不写数据库。
- 外链为空、超出 `30 MiB`、格式无效或声明哈希冲突：该照片失败并保留原记录。
- OSS HEAD 与上传结果不一致：不得切换数据库；保留确定性对象供恢复核验，不自动删除。
- 数据库行在下载期间变化：标记并发冲突，不覆盖新数据。
- 资源或健康停止门禁触发：安全停止，保留批次 ID 和报告，以 `--resume` 继续。
- OSS 对象不存在、签名失效或哈希不符：在本机导出报告中列为失败，不回写生产库，不修改 OSS。
- 本机磁盘空间不足：生成文件前停止，报告预计体积和所需空间。
- 部分下载失败：保留已成功文件与清单，不宣称完整导出；用户可选择只重试失败项。

## 10. 测试与验收

### 10.1 自动化测试

- 路由测试证明 `/exports`、`/exports/*` 和遗留导出接口统一返回 `410`。

- 记录 API/worker 内存、服务状态、发布包 SHA256、release 路径和回滚目标。

## 11. 发布与回滚

V3.2.3 使用新的 `production/V3/3.2.3` 维护分支和版本化 release。发布前备份 `.env`、PostgreSQL、`data`、`uploads` 和当前 release，校验备份及发布包 SHA256。切换后等待 Uvicorn 端口就绪，再执行完整生产验收。

应用回滚恢复到 V3.2.2 release，但默认保留 Nginx 的 `/exports` 紧急拦截，避免旧版本重新暴露危险入口。只有用户明确要求恢复网页导出且已提供新的性能安全设计时，才允许移除 Nginx 拦截。

外链迁移在 V3.2.3 应用验收通过后单独执行。需要回退某一迁移批次时使用 `--rollback-run <id>` 恢复该批次保存的照片存储字段，并按证据版本规则重新失效相关资料组；回退不删除 OSS 对象，也不移除 Nginx 拦截。

服务器 release 清理必须先 dry-run，只保留最近五个可回滚 release，不得触碰 `.env`、`data`、`uploads`、`backups`、数据库 dump 或 OSS。

## 12. 验收结论标准

只有同时满足以下条件，才能报告“导出中心已下线”：

1. Nginx 和应用层均阻止旧导出入口。
2. 打开任何现存业务页面不会触发导出中心查询。
3. 后台不会生成最终交付 ZIP 或交付包缓存。
4. 条码扫描、施工、审阅、数据中台、驾驶舱和 KPI 查询无回归。
5. 发布记录包含备份、哈希、回滚、服务状态、内存和线上接口证据。

只有同时满足以下条件，才能报告“有效外链照片已迁入 OSS”：

1. V3.2.3 已停止所有交付缓存和最终包排队、领取及生成。
2. dry-run、十张试迁移和全量对账均留有可审计报告。
3. 有效 `external_url` 数量为 `0`，失败和冲突数量为 `0`；空或未知类型仍明确单列。
4. 每个切换记录均有 OSS HEAD、大小、实际内容 SHA256 和 `raw_data.pre_oss_*` 证据。
5. 迁移未覆盖、移动或删除任何已有 OSS 对象，未删除原外链审计信息。
6. 已验证一条假 OSS 到本机的导出流程，并能输出数量、失败清单和 SHA256。
