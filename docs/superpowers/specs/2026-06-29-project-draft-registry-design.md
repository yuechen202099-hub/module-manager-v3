# 项目接入草稿层设计

日期：2026-06-29

## 背景

当前平台已经具备项目模块注册、按项目模块读取、以及生产基线跟进检查。项目总览页仍然只有“更换模块项目”这个生产项目，“新建项目”按钮也只是提示接口待接入。为了让网站逐步从单项目管理器变成运维工程管理平台，下一步需要让其他项目先能进入平台列表，并能声明自己启用哪些管理模块。

本设计只做项目接入草稿层，不做生产数据库迁移，不直接修改 OSS 或 PostgreSQL 生产数据，不绑定真实施工、审阅或交付数据源。

## 目标

- 管理员可以在项目管理页创建一个平台项目草稿。
- 草稿项目可以选择启用的模块，例如项目进度、交付能力、现场采集、审阅功能、风险、任务中心。
- 创建后的项目会出现在项目列表中，并能被选中。
- 草稿项目的模块入口来自后端模块 registry，不在前端写死。
- 草稿项目初期显示为空状态，用于后续接入真实 adapter。

## 非目标

- 不设计完整项目模板市场。
- 不引入数据库迁移。
- 不把草稿项目写入生产 PostgreSQL。
- 不直接读写生产 OSS 对象。
- 不改变“更换模块项目”的现有生产数据汇总逻辑。
- 不实现真实项目数据导入、同步或业务 adapter 绑定。
- 不实现复杂审批流、权限配置器或客户门户。

## 推荐方案

采用“内存/开发态项目 registry + 后端统一接口 + 前端创建弹窗”的方式。

现有 `replacement-project` 保持静态生产项目定义。新增草稿项目在当前应用进程内注册为 `draft` 状态，返回空的项目概览和所选模块清单。后续如果确认需要持久化，再单独设计数据库表、迁移、备份和回滚路径。

这个方案的优势是风险低、反馈快、不会触碰生产数据；缺点是重启后草稿会丢失。因此前端文案和接口行为必须明确这是“接入草稿”，不是正式生产项目配置。

## 后端设计

### 数据结构

新增平台项目草稿模型，字段包括：

- `id`：由名称生成的稳定 slug，冲突时追加序号。
- `name`：项目名称，必填。
- `description`：项目说明，可选。
- `status`：固定为 `draft`。
- `adapter`：固定为 `draft`。
- `module_ids`：启用模块 id 列表。
- `created_at`：创建时间。
- `updated_at`：更新时间。

草稿项目使用现有 `ProjectDefinition` 和 `ProjectModuleDefinition` 语义，不新增与生产业务数据耦合的字段。

### 接口行为

`POST /projects`

请求：

```json
{
  "name": "新项目名称",
  "description": "项目说明",
  "module_ids": ["progress", "delivery", "field", "review"]
}
```

响应返回完整项目概览，结构与 `GET /projects/{project_id}` 一致。草稿项目的概览字段为安全空值：

- 进度为 0。
- 组数为 0。
- 风险为 0。
- 交付为准备中。
- 审阅、现场、任务等模块只在启用时返回对应空 section。
- `modules` 只返回项目启用的模块，并按 priority 排序。

`GET /projects`

返回生产项目和当前进程内草稿项目。生产项目仍按现有 adapter 汇总，草稿项目按空概览返回。

`GET /projects/{project_id}`

草稿项目返回空概览。未知项目返回 404。

`GET /projects/{project_id}/modules`

草稿项目返回自己启用的模块清单。

`GET /projects/{project_id}/modules/{module_id}`

启用模块返回对应空 section。未启用模块返回 404。

### 校验规则

- `name` 去掉首尾空格后不能为空。
- `module_ids` 不能为空。
- 所有 `module_ids` 必须存在于后端模块 registry。
- `module_ids` 去重后按模块 priority 输出。
- 草稿项目 id 不得覆盖现有生产项目 id。
- 无效配置返回 400；未知项目返回 404；项目配置错误仍按现有规则返回 500。

## 前端设计

### 项目页交互

项目管理页“新建项目”按钮打开弹窗，而不是只提示待接入。

弹窗字段：

- 项目名称。
- 项目说明。
- 启用模块多选。

默认选中模块：

1. 项目进度
2. 项目交付能力
3. 现场施工数据采集
4. 审阅功能

风险和任务中心可选中，但不强制。

提交成功后：

- 关闭弹窗。
- 刷新项目列表。
- 自动选中新建项目。
- 显示创建成功提示。

### 空状态

草稿项目在列表中可以显示：

- 状态：草稿。
- 阶段：准备中。
- 进度：0。
- 交付：准备中。
- 风险：0。

模块按钮仍可进入对应页面，但这些页面后续要逐步识别草稿项目并展示空状态。本阶段只保证项目列表和模块读取接口正确，不要求每个业务页面都完成草稿专属体验。

## 数据流

```mermaid
flowchart LR
  A["项目管理页"] --> B["POST /projects"]
  B --> C["草稿项目 registry"]
  C --> D["GET /projects"]
  D --> E["项目列表"]
  E --> F["按 modules 读取 section"]
```

## 错误处理

- 名称为空：前端阻止提交，后端返回 400。
- 模块未选择：前端阻止提交，后端返回 400。
- 模块 id 不存在：后端返回 400。
- 创建失败：弹窗保持打开，展示错误提示。
- 刷新列表失败：保留当前页面状态，展示错误提示。

## 测试与验证

后端测试：

- `POST /projects` 创建草稿项目后返回完整概览。
- `GET /projects` 包含草稿项目。
- 草稿项目模块列表按 priority 排序。
- 未启用模块 section 返回 404。
- 名称为空、模块为空、未知模块返回 400。
- 生产项目 `replacement-project` 行为不变。

前端验证：

- 项目页不再出现“项目创建接口待接入”。
- 项目页调用 `createProject` 服务。
- 创建弹窗包含名称、说明、模块选择。
- 创建成功后刷新项目列表并选中新项目。
- 现有模块 metadata 和 module path 验证继续通过。

## 风险与边界

- 草稿项目当前不持久化，服务重启后会丢失；这是刻意的低风险边界。
- 草稿项目不是生产项目配置，不参与生产发布、交付和真实业务统计。
- 后续若要持久化，必须另起数据库设计，明确备份、迁移、回滚路径。
- 任何真实数据源绑定都必须通过 adapter 增量接入，不能让草稿项目绕过现有业务硬规则。

## 实施拆分

建议分三步实施：

1. 后端草稿项目 registry 和接口契约。
2. 前端项目创建弹窗和 API 服务。
3. 构建产物刷新、验证脚本增强、代码审阅和提交。

## 待确认

- 草稿项目是否允许重启后丢失，直到后续持久化设计完成。
- 默认模块是否采用“进度、交付、现场、审阅”四项。
- 草稿项目是否只允许管理员创建。
