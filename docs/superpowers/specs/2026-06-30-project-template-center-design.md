# Project Template Center Design

## Goal

Build the first version of a project template center so each configured project can download Excel templates for initial work orders, field collection, and externally completed work.

## Scope

The first version focuses on template generation and safe simulation data. Import execution can follow once the template contract is visible and stable.

## Template Types

- `initial_work_orders`: fields that can be imported before construction starts, including the primary field, aggregate field, and custom fields whose source is `import`.
- `field_collection`: fields expected from site collection, including custom fields whose source is `field_collection`.
- `external_completed`: fields that an outside system can reasonably provide for already completed work. It includes the primary field, aggregate field, import fields, field collection fields, and optional evidence fields.

## External Completed Rules

Externally completed data must not be blocked by fields that only the platform can know.

- `uploaded_at` is filled by the platform at upload time.
- `completed_at` uses the imported value when present and upload time when missing.
- `installer` uses the imported value when present and the upload actor when missing.
- `work_order_id` is generated by the platform when missing.
- `photo_count` defaults to zero unless evidence columns provide a count.
- `online_duration_minutes` remains blank when the outside system cannot provide it.

## Workbook Shape

Each generated workbook has two sheets:

- `template`: header row, one example row, and one note row.
- `fields`: field key, label, source, capture method, data type, required flag, and whether the value is platform-filled for this template.

## Safety

Templates are generated from project schema and synthetic examples only. No production `.env`, uploads, databases, or real business spreadsheets are read or modified.
