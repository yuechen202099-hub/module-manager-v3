# V3.0.83 审阅图片框选识别与局部放大设计

## 目标

在桌面端“扫码未匹配审阅”和正常审阅工作台中增加同一套图片检查能力：管理员或审阅员可以在不打开大图的情况下局部放大照片，框选照片中的条码区域，明确选择表号、模块号或采集器号后执行条形码、二维码和 OCR 识别。识别结果必须经过人工确认，才可以写入当前页面对应的输入框；最终仍由原有保存操作入库并产生编辑审计。

## 核心约束

- 本次只支持桌面端，不增加移动端手势、布局或验收范围。
- 不提供“自动判断”分类。每次识别前必须人工选择 `meter`、`module` 或 `collector`。
- 区域识别是只读操作，不直接修改数据库、照片扫码状态、资料组状态或驾驶舱准确率。
- 人工确认识别结果后只更新前端草稿；管理员或审阅员仍可继续修改，点击原有“保存”后才入库。
- 已有字段与识别值不同时，不得静默覆盖；确认窗口必须同时展示原值和识别值。
- 不创建占位资料组、占位终端或 `00000000` 工单。
- 自动上传继续保持关闭，本功能不触碰施工采集和上传链路。
- 复用现有条形码、二维码、OCR、图片权限和审计能力，不在浏览器中实现另一套识别算法。

## 交互设计

两个审阅入口复用同一个桌面图片检查组件。

### 局部放大

- 普通查看模式下，鼠标悬停图片显示约 `2.5x` 的跟随式放大镜。
- 放大镜只复用当前已经加载的图片资源，不打开全屏大图，也不请求另一份原图。
- 现有双击打开完整大图能力保留，不改变既有审阅习惯。
- 放大镜和框选模式互斥；进入框选模式后暂停放大镜。

### 框选识别

1. 点击带图标的“框选扫码”按钮进入框选模式。
2. 在实际图片内容区域内拖动生成矩形选区；图片因 `object-fit: contain` 产生的留白不能成为选区。
3. 框选完成后显示三个条码分类选项：表号、模块号、采集器号。
4. 未选择分类时禁用“识别选区”。
5. 点击“识别选区”后只提交归一化坐标和人工选择的分类。
6. 识别失败时保留选区，允许重新识别或重新框选。
7. 点击“取消框选”恢复普通查看模式，不修改任何字段。

### 结果确认

- 无候选值：提示当前选区未识别到可用内容，不打开替换确认。
- 单个候选值：确认窗口直接展示该值。
- 多个候选值：管理员或审阅员必须通过单选框选择一个值。
- 确认窗口展示条码分类、原值、识别值和识别方式。
- 点击“替换”后只写入当前页面对应输入框；点击“取消”后原值不变。
- 正常审阅写入 `metadataDraft.meterNo`、`metadataDraft.moduleAssetNo` 或 `metadataDraft.collector`。
- 未匹配审阅写入 `draft.meterNo`、`draft.moduleAssetNo` 或 `draft.collector`。
- 区域识别不会自动把照片或资料组标记为扫码通过；现有重新扫码和人工确认规则继续负责正式扫码状态。

## 前端架构

新增共享组件 `v2-web/src/components/ReviewImageInspector.vue`，由 `UnmatchedReviewDialog.vue` 和 `TaskHallView.vue` 使用。组件只负责图片几何和交互，不直接调用具体业务接口。

建议接口：

```ts
type BarcodeType = 'meter' | 'module' | 'collector'

type NormalizedRegion = {
  x: number
  y: number
  width: number
  height: number
}

type RegionScanRequest = {
  barcodeType: BarcodeType
  region: NormalizedRegion
}
```

组件职责：

- 渲染主图、加载状态和错误状态。
- 根据图片 `naturalWidth`、`naturalHeight`、容器尺寸和 `object-fit: contain` 计算实际图片内容矩形。
- 将指针坐标限制在图片内容矩形内，并转换成 `0..1` 的归一化原图坐标。
- 管理普通、放大、框选和识别中状态；同一时刻只允许一个识别请求。
- 在图片切换、弹窗关闭或请求过期时清空选区并忽略旧响应。
- 通过事件把选区和分类交给父页面；父页面选择正常资料组接口或未匹配接口，并负责把人工确认结果写入各自草稿。

组件不增加可见的使用说明文字。陌生图标通过 tooltip 说明，按钮使用现有 Element Plus 图标和控件风格。

## 服务端接口

新增两个只读接口，沿用现有 `/local-test` 审阅权限边界：

| 接口 | 作用 |
| --- | --- |
| `POST /local-test/groups/{group_id}/photos/{photo_id}/region-scan` | 识别正常资料组的一张照片选区 |
| `POST /local-test/unmatched/{unmatched_id}/photos/{photo_id}/region-scan` | 识别未匹配临时审阅的一张照片选区 |

请求体：

```json
{
  "barcode_type": "module",
  "region": {
    "x": 0.25,
    "y": 0.30,
    "width": 0.40,
    "height": 0.18
  }
}
```

响应体只返回识别候选，不返回任意服务器文件路径：

```json
{
  "barcode_type": "module",
  "values": ["3130001122100009124734"],
  "normalized_values": ["3130001122100009124734"],
  "method": "barcode",
  "region": {
    "x": 0.25,
    "y": 0.30,
    "width": 0.40,
    "height": 0.18
  }
}
```

服务端根据路由中的资料组、未匹配记录和照片 ID 查找受信任图片来源，不接受客户端提交 URL、文件路径或图片二进制。正常资料组入口和未匹配入口最终调用同一个区域识别服务。

区域识别服务按以下顺序工作：

1. 校验分类只能是 `meter`、`module` 或 `collector`。
2. 校验 `x`、`y`、`width`、`height` 为有限数值，均在 `0..1` 内且矩形不越界。
3. 读取原图并按 EXIF 信息修正方向，使服务端裁剪方向与浏览器显示一致。
4. 将归一化坐标转换为像素坐标，拒绝小于安全阈值的选区。
5. 只裁剪选区，并复用现有图片尺寸、候选数量、旋转增强和 CPU 安全限制。
6. 先执行条形码和二维码识别；没有可靠候选时再执行按需 OCR。
7. 标准化并去重候选值后返回，不根据长度或前缀猜测条码分类。

## 权限与安全

- 正常资料组接口沿用正常审阅的管理员和审阅员权限。
- 未匹配接口沿用未匹配临时审阅权限；施工员不能访问。
- 前端隐藏按钮不作为权限控制，两个接口都必须在服务端鉴权。
- 不允许通过请求指定外部 URL，避免 SSRF 和越权读取其他照片。
- 沿用现有图片解码尺寸上限、OCR 次数上限和候选数量上限，防止单次请求拉高服务器负载。
- 同一页面只允许一个区域识别请求；没有后台批量任务、自动重试或并行扫描。
- 选区裁剪图不保存到磁盘、数据库或日志。
- 登录过期继续由全局认证处理跳转登录页。

## 数据与审计边界

框选、放大、识别请求和取消确认均为只读行为，不产生业务数据修改。点击“替换”也只修改浏览器草稿，不单独写数据库。

用户点击原有“保存”后，继续由既有保存接口记录操作人、时间、修改前后值和实体 ID。未匹配审阅继续使用版本号防止并发覆盖；发生 `409` 时保留本地草稿并提示重新加载。区域识别结果本身不改变：

- `barcode_check_status`
- `barcode_check_matched_value`
- 资料组扫码通过数量
- 驾驶舱条码准确率
- 归档状态
- 未匹配记录关联状态

## 错误处理

- 图片不存在或无权访问：返回 `404` 或 `403`，不泄露图片来源。
- 坐标非法、选区过小或分类缺失：返回 `422`，保留页面原值。
- 图片解码或识别超时：返回明确失败信息，不自动重试。
- 未识别到候选：返回空列表，允许用户重新框选。
- 多候选：必须人工单选，未选择时禁用“替换”。
- 切换图片、资料组或未匹配记录后返回的旧响应：前端丢弃。
- 保存时版本冲突：沿用现有 `409` 处理，不覆盖其他管理员的新数据。
- 任意失败都不能改变照片扫码状态、输入框原值或持久化数据。

## 测试策略

先补测试，再修改实现。

### 后端

1. 正常资料组和未匹配入口都校验管理员或审阅员权限。
2. 施工员、跨团队请求和不存在照片不能读取或识别图片。
3. 非法分类、非有限坐标、越界坐标和过小选区返回 `422`。
4. EXIF 旋转照片的选区映射与浏览器显示方向一致。
5. 条形码、二维码和 OCR 分别能从选区返回候选值。
6. 多候选值被标准化和去重，但不会自动选择分类或写入字段。
7. 无法识别时返回空候选，不覆盖已有扫码证据。
8. 区域识别前后资料组、照片、准确率和归档状态完全不变。
9. 原图读取、图片尺寸、OCR 次数和候选数量安全限制继续生效。
10. 现有整图重新扫码、人工确认和未匹配审阅接口保持兼容。

### 前端

1. `object-fit: contain` 产生留白时，选区只能落在实际图片区域。
2. 显示选区正确转换为归一化原图坐标。
3. 悬停放大镜不打开大图，也不发起另一份原图请求。
4. 框选模式暂停放大镜；取消后恢复普通查看。
5. 未选择表号、模块号或采集器号时不能提交识别。
6. 多候选必须人工单选。
7. 原值和识别值不同时展示替换确认；取消后原值不变。
8. 三种分类分别写入正确草稿字段，不直接调用保存接口。
9. 切换图片或关闭弹窗后忽略过期识别响应。
10. 未匹配审阅和正常审阅都使用共享组件，不复制两套坐标逻辑。

### 浏览器验收

- 桌面端正常审阅完成一次局部放大、框选模块号、识别、人工替换和保存。
- 桌面端未匹配审阅完成一次局部放大、框选表号、识别、多候选选择、人工替换和保存。
- 验证失败请求不修改输入框和扫码状态。
- 验证控制台无错误，网络请求不重复加载大图，服务端 CPU 无异常峰值。
- 本次不执行手机端布局和触摸交互验收。
