# V3.0.83 审阅图片框选识别、局部放大与终端优先施工设计

## 目标

本版本包含两个生产功能：

1. 在桌面端“扫码未匹配审阅”和正常审阅工作台中增加同一套图片检查能力。管理员或审阅员可以在不打开大图的情况下局部放大照片，框选照片中的条码区域，明确选择表号、模块号或采集器号后执行条形码、二维码和 OCR 识别。识别结果必须经过人工确认，才可以写入当前页面对应的输入框；最终仍由原有保存操作入库并产生编辑审计。
2. 管理员可以给终端任务设置“优先施工”标识，支持单条修改和 Excel 批量导入。任务领取页按“全部、优先施工、可施工、可领取审阅”筛选，明确区分施工派发和审阅领取范围。

## 核心约束

- 本次只支持桌面端，不增加移动端手势、布局或验收范围。
- 不提供“自动判断”分类。每次识别前必须人工选择 `meter`、`module` 或 `collector`。
- 区域识别是只读操作，不直接修改数据库、照片扫码状态、资料组状态或驾驶舱准确率。
- 人工确认识别结果后只更新前端草稿；管理员或审阅员仍可继续修改，点击原有“保存”后才入库。
- 已有字段与识别值不同时，不得静默覆盖；确认窗口必须同时展示原值和识别值。
- 不创建占位资料组、占位终端或 `00000000` 工单。
- 自动上传继续保持关闭，本功能不触碰施工采集和上传链路。
- 复用现有条形码、二维码、OCR、图片权限和审计能力，不在浏览器中实现另一套识别算法。
- “优先施工”是唯一的人工优先级，不增加高、中、低等级。
- 优先标识绑定到终端任务，不绑定领取人、施工员或单次指派记录；领取、释放和改派不能清除未完成终端的标识。
- “可施工”和“可领取审阅”由服务端完成量计算，不允许管理员手工修改。
- 终端施工上传达到 100% 时自动清除优先标识；回退为未施工后旧标识不能恢复。

## 交互设计

两个审阅入口复用同一个桌面图片检查组件。

### 局部放大

- 普通查看模式下，鼠标悬停图片显示约 `2.5x` 的跟随式放大镜。
- 放大镜只复用当前已经加载的图片资源，不打开全屏大图，也不请求另一份原图。
- 现有双击打开完整大图能力保留，不改变既有审阅习惯。
- 放大镜和框选模式互斥；进入框选模式后暂停放大镜。

### 框选识别

1. 点击带图标的“框选扫码”按钮进入框选模式。
2. 在实际图片内容区域内拖动生成矩形选区；图片因 `object-fit: contain` 产生的留白不能成为选区。
3. 框选完成后显示三个条码分类选项：表号、模块号、采集器号。
4. 未选择分类时禁用“识别选区”。
5. 点击“识别选区”后只提交归一化坐标和人工选择的分类。
6. 识别失败时保留选区，允许重新识别或重新框选。
7. 点击“取消框选”恢复普通查看模式，不修改任何字段。

### 结果确认

- 无候选值：提示当前选区未识别到可用内容，不打开替换确认。
- 单个候选值：确认窗口直接展示该值。
- 多个候选值：管理员或审阅员必须通过单选框选择一个值。
- 确认窗口展示条码分类、原值、识别值和识别方式。
- 点击“替换”后只写入当前页面对应输入框；点击“取消”后原值不变。
- 正常审阅写入 `metadataDraft.meterNo`、`metadataDraft.moduleAssetNo` 或 `metadataDraft.collector`。
- 未匹配审阅写入 `draft.meterNo`、`draft.moduleAssetNo` 或 `draft.collector`。
- 区域识别不会自动把照片或资料组标记为扫码通过；现有重新扫码和人工确认规则继续负责正式扫码状态。

## 前端架构

新增共享组件 `v2-web/src/components/ReviewImageInspector.vue`，由 `UnmatchedReviewDialog.vue` 和 `TaskHallView.vue` 使用。组件只负责图片几何和交互，不直接调用具体业务接口。

建议接口：

```ts
type BarcodeType = 'meter' | 'module' | 'collector'

type NormalizedRegion = {
  x: number
  y: number
  width: number
  height: number
}

type RegionScanRequest = {
  barcodeType: BarcodeType
  region: NormalizedRegion
}
```

组件职责：

- 渲染主图、加载状态和错误状态。
- 根据图片 `naturalWidth`、`naturalHeight`、容器尺寸和 `object-fit: contain` 计算实际图片内容矩形。
- 将指针坐标限制在图片内容矩形内，并转换成 `0..1` 的归一化原图坐标。
- 管理普通、放大、框选和识别中状态；同一时刻只允许一个识别请求。
- 在图片切换、弹窗关闭或请求过期时清空选区并忽略旧响应。
- 通过事件把选区和分类交给父页面；父页面选择正常资料组接口或未匹配接口，并负责把人工确认结果写入各自草稿。

组件不增加可见的使用说明文字。陌生图标通过 tooltip 说明，按钮使用现有 Element Plus 图标和控件风格。

## 服务端接口

新增两个只读接口，沿用现有 `/local-test` 审阅权限边界：

| 接口 | 作用 |
| --- | --- |
| `POST /local-test/groups/{group_id}/photos/{photo_id}/region-scan` | 识别正常资料组的一张照片选区 |
| `POST /local-test/unmatched/{unmatched_id}/photos/{photo_id}/region-scan` | 识别未匹配临时审阅的一张照片选区 |

请求体：

```json
{
  "barcode_type": "module",
  "region": {
    "x": 0.25,
    "y": 0.30,
    "width": 0.40,
    "height": 0.18
  }
}
```

响应体只返回识别候选，不返回任意服务器文件路径：

```json
{
  "barcode_type": "module",
  "values": ["3130001122100009124734"],
  "normalized_values": ["3130001122100009124734"],
  "method": "barcode",
  "region": {
    "x": 0.25,
    "y": 0.30,
    "width": 0.40,
    "height": 0.18
  }
}
```

服务端根据路由中的资料组、未匹配记录和照片 ID 查找受信任图片来源，不接受客户端提交 URL、文件路径或图片二进制。正常资料组入口和未匹配入口最终调用同一个区域识别服务。

区域识别服务按以下顺序工作：

1. 校验分类只能是 `meter`、`module` 或 `collector`。
2. 校验 `x`、`y`、`width`、`height` 为有限数值，均在 `0..1` 内且矩形不越界。
3. 读取原图并按 EXIF 信息修正方向，使服务端裁剪方向与浏览器显示一致。
4. 将归一化坐标转换为像素坐标，拒绝小于安全阈值的选区。
5. 只裁剪选区，并复用现有图片尺寸、候选数量、旋转增强和 CPU 安全限制。
6. 先执行条形码和二维码识别；没有可靠候选时再执行按需 OCR。
7. 标准化并去重候选值后返回，不根据长度或前缀猜测条码分类。

## 终端优先施工

### 状态规则

服务端为任务接口返回三个明确字段：

```text
construction_priority   管理员保存的优先施工标识
construction_available total_groups > 0 且 uploaded_count < total_groups
review_available       uploaded_count > 0 且 unreviewed_count > 0
```

页面展示使用有效优先状态：

```text
effective_construction_priority = construction_priority 且 construction_available
```

因此：

- 上传数量为 `0` 且终端未完成时，只属于“可施工”。
- 上传数量大于 `0`、小于总数且仍有未审阅资料时，同时属于“可施工”和“可领取审阅”。
- 上传达到总数时，不再属于“可施工”，并自动清除“优先施工”；若仍有未审阅资料，只属于“可领取审阅”。
- 审阅完成不会改变施工进度，也不会单独清除未完成终端的优先标识。
- 总资料组数量为 `0` 的异常任务不属于“可施工”或“可领取审阅”，也不能标记优先施工。

自动清除必须发生在施工上传成功并使任务达到 100% 的同一业务事务中。任务响应层同时做防御性处理：即使历史脏数据仍保存了优先值，完成终端也只能返回无效优先状态。数据库迁移时把已经 100% 完成的任务统一回填为非优先。

### 任务领取页

管理员看到四个分段筛选：

- 全部
- 优先施工
- 可施工
- 可领取审阅

页面沿用现有任务缓存，但筛选只使用服务端返回的状态字段，不在前端重复推算上传和审阅口径。在“全部”和“可施工”中，有效优先终端排在普通终端前面；同一优先级内保持现有任务排序规则。

任务卡片按状态展示紧凑标签：

- 有效优先状态展示“优先施工”。
- `construction_available=true` 展示“可施工”。
- `review_available=true` 展示“可领取审阅”。
- 达到 100% 后“优先施工”和“可施工”同时消失。

管理员可在任务卡片“更多”菜单中执行“设为优先施工”或“取消优先施工”。已完成、零资料组或无权操作的终端不显示可执行入口。审阅员继续只看到有待审资料的终端，不获得施工指派或优先标记权限。

任务列表工具栏增加“批量标记”按钮，仅管理员可见。按钮打开弹窗，不跳转新页面。弹窗包含模板下载、文件选择、预览结果、错误清单和确认导入；预览与错误明细统一按每页 20 条分页，不一次渲染整份文件，也不增加解释性页面文字。

### 批量导入

Excel 模板固定为两个中文列名：

```text
终端号 | 优先施工
```

“优先施工”接受模板下拉值“是”或“否”。服务端按字符串规范化终端号，不由 Excel 自动转换或截断长编号。

导入采用两阶段流程：

1. 预览：上传文件并返回有效、重复、冲突、未找到、已完成、无需变更和格式错误数量及逐行结果。
2. 确认：浏览器保留同一个文件并再次提交，服务端重新解析和校验当前任务状态后才写入。

导入规则：

- 同一终端重复且值一致时合并为一条，不重复写审计。
- 同一终端同时出现“是”和“否”时视为冲突，禁止确认导入。
- 未找到的终端、已完成终端和零资料组终端不修改，明确列入跳过清单。
- 与当前值相同的终端计为“无需变更”，不重复写数据库。
- 格式错误或冲突重复存在时禁止确认；其余有效行在一个事务中提交。
- 确认阶段发现任务已达到 100% 时重新判定为跳过，不能把完成终端改回优先。
- 限制文件类型、文件大小和最大行数，避免批量接口影响生产服务器。

## 终端优先数据与接口

PostgreSQL `tasks` 表增加明确字段，不把业务标识藏入 `raw_data`：

```text
construction_priority            boolean, not null, default false
construction_priority_updated_by varchar(64), nullable
construction_priority_updated_at timestamptz, nullable
```

JSON 状态后端保留等价字段，用于现有本地测试和回退兼容。任务序列化同时返回蛇形字段，前端服务层映射成 `constructionPriority`、`constructionAvailable` 和 `reviewAvailable`。

新增管理员接口：

| 接口 | 作用 |
| --- | --- |
| `PATCH /local-test/construction/tasks/{task_id}/priority` | 单条设置或取消优先施工 |
| `GET /local-test/construction/priority-template` | 下载 Excel 模板 |
| `POST /local-test/construction/priority-import?confirm=false` | 解析并预览批量文件 |
| `POST /local-test/construction/priority-import?confirm=true` | 重新校验并提交批量文件 |

单条修改请求体只接受布尔值：

```json
{ "priority": true }
```

所有查询和修改按当前项目团队隔离。单条修改、批量提交和上传完成自动清除后，都必须使现有任务状态版本失效，促使任务领取页更新缓存。

## 权限与安全

- 正常资料组接口沿用正常审阅的管理员和审阅员权限。
- 未匹配接口沿用未匹配临时审阅权限；施工员不能访问。
- 前端隐藏按钮不作为权限控制，两个接口都必须在服务端鉴权。
- 不允许通过请求指定外部 URL，避免 SSRF 和越权读取其他照片。
- 沿用现有图片解码尺寸上限、OCR 次数上限和候选数量上限，防止单次请求拉高服务器负载。
- 同一页面只允许一个区域识别请求；没有后台批量任务、自动重试或并行扫描。
- 选区裁剪图不保存到磁盘、数据库或日志。
- 登录过期继续由全局认证处理跳转登录页。
- 只有管理员可以单条设置、取消、预览和提交优先施工批量文件。
- 审阅员可以看到权限范围内任务的状态标签，但不能修改优先标识或下载管理模板。
- 批量导入只按当前团队查找终端；其他团队同名终端不能被读取或修改。
- 服务端读取 Excel 时不执行公式、宏、外部链接或嵌入对象。
- 单条标记和批量提交都在写入前锁定任务并重新检查施工完成状态，避免与最后一组上传竞争。

## 数据与审计边界

框选、放大、识别请求和取消确认均为只读行为，不产生业务数据修改。点击“替换”也只修改浏览器草稿，不单独写数据库。

用户点击原有“保存”后，继续由既有保存接口记录操作人、时间、修改前后值和实体 ID。未匹配审阅继续使用版本号防止并发覆盖；发生 `409` 时保留本地草稿并提示重新加载。区域识别结果本身不改变：

- `barcode_check_status`
- `barcode_check_matched_value`
- 资料组扫码通过数量
- 驾驶舱条码准确率
- 归档状态
- 未匹配记录关联状态

优先施工的单条修改为每个终端记录操作人、时间、任务 ID、终端号和修改前后值。批量提交同时记录一条批次摘要和每个实际变化终端的明细；重复、跳过和无需变更行只进入批次摘要，不伪造业务变更审计。施工达到 100% 自动清除时使用明确的系统动作名，并记录触发上传的操作人和任务完成数据。

## 错误处理

- 图片不存在或无权访问：返回 `404` 或 `403`，不泄露图片来源。
- 坐标非法、选区过小或分类缺失：返回 `422`，保留页面原值。
- 图片解码或识别超时：返回明确失败信息，不自动重试。
- 未识别到候选：返回空列表，允许用户重新框选。
- 多候选：必须人工单选，未选择时禁用“替换”。
- 切换图片、资料组或未匹配记录后返回的旧响应：前端丢弃。
- 保存时版本冲突：沿用现有 `409` 处理，不覆盖其他管理员的新数据。
- 任意失败都不能改变照片扫码状态、输入框原值或持久化数据。
- 非管理员修改优先标识返回 `403`。
- 终端不存在或不属于当前团队返回 `404`，不泄露其他团队数据。
- 已完成或零资料组终端设置优先返回业务错误，取消优先仍保持幂等。
- 批量文件表头错误、值不是“是/否”、冲突重复或超过限制时禁止确认。
- 批量确认前重新解析原文件；文件损坏或状态变化时展示新的跳过及错误结果，不沿用旧预览盲目写入。
- 单条标记、批量提交和最后一组施工上传并发时，以任务行锁和最新完成量为准；完成终端最终必须是非优先。

## 测试策略

先补测试，再修改实现。

### 后端

1. 正常资料组和未匹配入口都校验管理员或审阅员权限。
2. 施工员、跨团队请求和不存在照片不能读取或识别图片。
3. 非法分类、非有限坐标、越界坐标和过小选区返回 `422`。
4. EXIF 旋转照片的选区映射与浏览器显示方向一致。
5. 条形码、二维码和 OCR 分别能从选区返回候选值。
6. 多候选值被标准化和去重，但不会自动选择分类或写入字段。
7. 无法识别时返回空候选，不覆盖已有扫码证据。
8. 区域识别前后资料组、照片、准确率和归档状态完全不变。
9. 原图读取、图片尺寸、OCR 次数和候选数量安全限制继续生效。
10. 现有整图重新扫码、人工确认和未匹配审阅接口保持兼容。
11. 数据库迁移为旧任务提供 `false` 默认值，并清除已经 100% 完成任务的历史优先值。
12. 单条设置和取消优先施工只允许管理员，且领取、释放和改派不会丢失标识。
13. `construction_available` 和 `review_available` 覆盖 `0%`、`1%..99%`、`100%`、全部已审和零资料组组合。
14. 最后一组上传成功后在同一业务事务中清除优先标识并写审计。
15. 回退为未施工后不会恢复已经清除的旧优先标识。
16. 批量预览覆盖有效、同值重复、冲突重复、未找到、已完成、无需变更和格式错误。
17. 批量确认重新校验状态，只提交有效变化，且同一终端只写一次审计。
18. 跨团队同名终端、公式单元格、超大文件和非管理员导入均被拒绝。
19. 单条和批量修改都会更新任务状态版本，旧页面缓存不会长期保留旧标签。

### 前端

1. `object-fit: contain` 产生留白时，选区只能落在实际图片区域。
2. 显示选区正确转换为归一化原图坐标。
3. 悬停放大镜不打开大图，也不发起另一份原图请求。

13. “全部”和“可施工”筛选中优先终端在普通终端之前。
14. 单条标记成功后更新当前卡片和缓存；失败时恢复原状态。
