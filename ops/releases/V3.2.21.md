## Scope

- When the current material group has no open anomaly, formal approval keeps the existing behavior.
- When open anomalies exist, the review panel displays their count and asks whether all have been manually verified and fixed.
- Confirmation sends the exact anomaly code and evidence-fingerprint snapshot shown to the administrator.
- JSON and PostgreSQL backends re-check the snapshot under the existing write transaction, resolve every current anomaly, create aggregate audit evidence, and approve the same group atomically.
- Changed evidence returns HTTP 409 and reloads current anomalies without approval.
- The operation is limited to the current material group and existing administrator authorization.
- The V3.2.20 meter number deduplication, constructed and unconstructed merge behavior, and effective collector number/module display remain unchanged.
- No database migration, production business-data rewrite, OSS write, camera request, or client-platform request is part of this release.
