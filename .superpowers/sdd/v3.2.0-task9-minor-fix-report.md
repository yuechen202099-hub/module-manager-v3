# V3.2.0 Task 9 Minor Fix Report

## Summary

`PostgresStateRepository.create_export_job()` now keeps explicit ownership of newly
written inline export content until the PostgreSQL transaction commits. A single
context-managed cleanup exit removes owned content on request-key reuse,
`IntegrityError` fallback, session setup failures, and other pre-commit
exceptions. Successful commits release cleanup ownership immediately.

The JSON repository was not changed.

## Independent Review Remediation

The independent review found that the first ownership guard was entered only
after `inline_export_request_key()`, and that the reused-file assertion did not
exercise an actual existing-job row.

### Remediation

- Established `_UncommittedExportContentGuard` before inline content generation.
- Registered `content_path` immediately after `write_export_content()` returned
  and before request-key calculation.
- Cleaned registered content on pre-session exceptions while preserving the
  original exception object and traceback.
- Added a request-key failure regression that proves one exact cleanup.
- Replaced the unrelated reused-file sentinel with a real existing
  `ExportJob.content_path`; the test proves the duplicate path is removed while
  the reused file remains byte-for-byte unchanged.
