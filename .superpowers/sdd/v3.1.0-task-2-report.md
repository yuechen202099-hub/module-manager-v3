## Delivered Behavior

- Construction slots `before_box`, `collector_barcode`, `module_meter`, and `after_box` directly become authoritative categories for JSON and PostgreSQL uploads. Eligibility now requires the same four categories.
- `invalidate_verification_for_group(session, group, actor, reason)` is used for photo add/delete/classification/rescan, identity changes, construction uploads, restore/replacement, and reset-to-unconstructed/unreviewed writes.
- Invalidation preserves prior audit history, clears passed/manual-confirmed evidence and legacy confirmation flags, and re-evaluates to `pending` or `not_eligible` from current evidence.
- Category corrections record group, photo, prior/new category, actor, timestamp, and invalidation reason without storage URL/key/credential data.
- Backfill is preview by default. Apply mode updates only active, unclassified photos with a unique valid construction slot; manual categories, conflicts, archived groups, inactive photos, and invalid slots are skipped.
- Storage-repair replacements now also use the common invalidation entry point in both JSON and PostgreSQL paths.
